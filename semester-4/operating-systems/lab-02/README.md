# TCP-клиент и UDP-сервер — лабораторная 2

Операционные системы, 4 семестр. Две программы для Windows на WinSock: TCP-клиент отправляет сообщения из файла, UDP-сервер принимает сообщения на диапазоне портов и подтверждает их номера.

## Сборка

Нужен C++-компилятор для Windows. Например, MinGW-w64:

```bash
mkdir build
g++ -std=c++17 -O2 tcpclient.cpp -lws2_32 -o build/tcpclient.exe
g++ -std=c++17 -O2 udpserver.cpp -lws2_32 -o build/udpserver.exe
```

При сборке MSVC используйте `cl /EHsc tcpclient.cpp /Febuild\tcpclient.exe` и аналогичную команду для `udpserver.cpp`. Библиотека WinSock указана через pragma.

## Использование

Строка входного файла: два телефона вида `+7` и десять цифр, время `HH:MM:SS` и текст до конца строки. Номера в примере демонстрационные:

```text
+70000000001 +70000000002 12:30:15 hello
```

```powershell
.\build\tcpclient.exe 127.0.0.1:9000 input.txt
.\build\udpserver.exe 9001 9003
```

Это разные протоколы: TCP-клиент проверяется с `tcpserveremul.rb`, UDP-сервер — с `udpclientemul.rb`. Для эмуляторов нужен Ruby, команды: `ruby tcpserveremul.rb 9000` и `ruby udpclientemul.rb 127.0.0.1:9001 input.txt`. Остальные два эмулятора сохранены для сравнения.

В сообщении передаются 32-битный индекс в network byte order, два телефона по 12 байт, три байта времени и текст с завершающим нулём. TCP начинается с команды `put`, ответ на сообщение — два байта `ok`. UDP подтверждает до 20 последних индексов; повторный индекс от того же IP и порта повторно не записывается в `msg.txt`.

UDP-сервер принимает до 64 клиентов, хранит до 512 индексов на клиента, слушает до 32 портов. Размер датаграммы ограничен 8192 байтами, строки TCP-клиента — 16 MiB. Сообщение `stop` завершает сервер. Протокол учебный, без шифрования и проверки отправителя; для демонстрации используйте localhost.

Проверки собранных программ: длинное TCP-сообщение, раздельное получение `o` и `k`, некорректный порт, отбрасывание повреждённых UDP-сообщений и обработка дубликатов:

```bash
python test_protocol.py
```
