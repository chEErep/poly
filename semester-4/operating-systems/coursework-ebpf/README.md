# Монитор системных вызовов на eBPF/BCC

Практическая часть курсовой по операционным системам, 4 семестр. Встроенная C-программа подключается к tracepoints `openat`, `execve`, `read` и `write`. Python получает события через perf buffer и выводит имя процесса, PID/TID, UID и параметры вызова.

Монитор фиксирует вход в syscall: для `read`/`write` показывается запрошенное число байтов. Результаты вызовов и фактически прочитанные или записанные байты здесь не измеряются.

## Окружение

Нужен Linux с поддержкой eBPF, BCC, headers для запущенного ядра и доступ к syscall tracepoints. Для обычного запуска используются права root. В Windows программа напрямую не работает; наличие WSL само по себе не гарантирует нужную конфигурацию ядра.

Проверка окружения ничего не устанавливает:

```bash
bash check_env.sh
```

В Ubuntu/Debian зависимости можно установить через `bash check_env.sh --install`. Скрипт запросит sudo для apt; headers должны соответствовать запущенному ядру. BCC устанавливается системным пакетом `python3-bpfcc`, а не одноимённым пакетом из PyPI.

## Демонстрация

В первом терминале:

```bash
sudo python3 monitor.py --only openat,execve --summary-every 5
```

Во втором:

```bash
bash test_workload.sh
```

Другие варианты:

```bash
sudo python3 monitor.py --pid 1234
sudo python3 monitor.py --comm python --summary-every 2
sudo python3 monitor.py --no-events --summary-every 2
```

`--pid` выбирает процесс по TGID, `--comm` — подстроку имени процесса (до 15 ASCII-символов). Фильтры выполняются до отправки события и обновления счётчиков. Сам монитор исключён из наблюдения, чтобы его вывод не создавал поток собственных событий `write`. Ctrl+C отсоединяет программу от tracepoints.

При заполнении perf buffer часть событий может потеряться: монитор отдельно выводит число потерь. Счётчики в BPF map продолжают считать отфильтрованные вызовы даже при потерях в потоке. Для высокой нагрузки используйте `--no-events`, чтобы сократить вывод в терминал. Имена файлов могут содержать чувствительные данные, поэтому сохранённый вывод нужно проверять перед публикацией.

Проверки Python-части не требуют BCC и root:

```bash
python3 -m unittest -v test_monitor.py
```

При подготовке этой версии проверены аргументы, форматирование, генерация фильтров и shell-скрипты. Полная загрузка eBPF в ядро в текущем окружении не проверена: в нём недоступны нужные tracepoints и headers.
