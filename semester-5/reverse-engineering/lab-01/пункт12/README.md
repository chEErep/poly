# Пункт 12 — бинарный обход защит

В этой папке сохранён `crackme_protected_patched.exe`: изменённая копия образца [`../binaries/crackme_protected.exe`](../binaries/crackme_protected.exe). Исходник `protected_main.c` для получения патча не менялся.

Рядом лежат `input.txt` и намеренно неверный `password.txt` со строкой `wrongpass`. Запуск из корня лабораторной:

```powershell
.\пункт12\crackme_protected_patched.exe
Get-Content .\пункт12\report.txt
Get-Content .\пункт12\serial.txt
```

Для входного примера ожидается успешное завершение и serial `KEY$0000001307$`, несмотря на неправильный пароль. `report.txt` и `serial.txt` генерируются при запуске и не входят в Git.

## Что изменено

В x64 Windows целочисленный результат этих функций возвращается через `EAX`. Начальные инструкции нескольких функций заменены короткими последовательностями:

- `B8 01 00 00 00 C3` — `mov eax, 1; ret`, вернуть успех.
- `31 C0 C3` — `xor eax, eax; ret`, вернуть отсутствие признака.
- `C3` — `ret`, немедленно выйти из функции типа `void`.

| Функция | RVA | Смещение в файле | Патч |
| --- | ---: | ---: | --- |
| `check_crc` | `0x1B52` | `0x1152` | Вернуть `1` |
| `debug_detected` | `0x1D59` | `0x1359` | Вернуть `0` |
| `vm_detected` | `0x2289` | `0x1889` | Вернуть `0` |
| `check_password` | `0xB000` | `0xA400` | Вернуть `1` |
| `false_check` | `0x1A59` | `0x1059` | Вернуть `0` |
| `check_password_sum` | `0x19F4` | `0x0FF4` | Вернуть `1` |
| `change_code` | `0x22CD` | `0x18CD` | Вернуть `1` |
| `disasm_jump` | `0x1DCC` | `0x13CC` | `ret` |
| `disasm_branch` | `0x1DDA` | `0x13DA` | `ret` |
| `disasm_overlap` | `0x1DEE` | `0x13EE` | `ret` |

Адреса относятся **только к сохранённой сборке**. Это один демонстрационный вариант обхода, а не доказательство минимальности набора изменений. Полезный анализ файла и `run_flow` оставлены работающими.

Для соответствующей секции:

```text
смещение в файле = PointerToRawData + (RVA − VirtualAddress)
адрес в памяти = фактическая база модуля + RVA
```

Из-за ASLR абсолютный адрес в x64dbg может меняться между запусками. Файловое смещение и адрес в памяти нельзя подставлять друг вместо друга.

## Почему обойдена CRC

Патч `check_password` меняет проверяемые байты `.pchk`, поэтому её CRC теперь `0xF4159BE4` вместо эталонной `0x8D686F4F`. Но начало `check_crc` тоже заменено на `mov eax, 1; ret`: функция больше не вычисляет CRC, а всегда сообщает успех.

Оригинал и патченый образец имеют одинаковый размер 120 725 байт и отличаются в 36 байтах. Это показывает ограничение локального самоконтроля: проверка целостности находится в том же изменяемом EXE.

Сравнивать следует сохранённые бинарники. После пересборки адреса, размеры и инструкции могут измениться.
