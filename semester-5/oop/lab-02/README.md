# ЛР 2 — Рефакторинг Flappy Bird

Объектная переработка процедурной игры Flappy Bird на Python и Pygame. Игровая логика отделена от обработки событий, отрисовки, звука и загрузки ресурсов. Основное поведение проверяется 18 unit-тестами стандартной библиотеки `unittest`.

## Возможности

- Заставка, полёт, завершение раунда и повторная попытка.
- Взмах, гравитация, покачивание и анимация птицы.
- Движущиеся пары труб со случайной высотой прохода.
- Однократный учёт прохождения каждого препятствия.
- Столкновения с землёй и проверка пересечения изображений по маскам пикселей.
- Смена оформления между раундами и звуковые эффекты.

## Запуск

Нужен Python 3.10 или новее. Проверенное окружение: Python 3.10.11, Pygame 2.6.1. Команды выполняются из `semester-5/oop/lab-02`.

Windows / PowerShell:

```powershell
py -3 -m venv .venv
& .\.venv\Scripts\python.exe -m pip install -r .\FlappyBird_refactored\requirements.txt
& .\.venv\Scripts\python.exe .\FlappyBird_refactored\main.py
```

Linux / macOS:

```sh
python3 -m venv .venv
.venv/bin/python -m pip install -r FlappyBird_refactored/requirements.txt
.venv/bin/python FlappyBird_refactored/main.py
```

Для игры нужны графическая среда и доступное аудиоустройство. Путь к ресурсам определяется относительно модуля загрузчика, поэтому запуск готовой версии не зависит от текущей рабочей папки.

**Управление:** пробел или стрелка вверх — начало игры и взмах; после проигрыша и приземления — возврат к заставке. Esc или закрытие окна — выход.

## Unit-тесты

Из папки лабораторной на Windows:

```powershell
Push-Location FlappyBird_refactored
& ..\.venv\Scripts\python.exe -B -m unittest discover -s tests -v
Pop-Location
```

На Linux / macOS:

```sh
cd FlappyBird_refactored
../.venv/bin/python -B -m unittest discover -s tests -v
```

Ожидаемый результат: `Ran 18 tests`, `OK`. Тесты не импортируют Pygame и не открывают окно. Для их запуска достаточно Python и исходных файлов, установка графической библиотеки нужна самой игре.

| Класс | Проверяемое поведение | Тестов |
|---|---|---:|
| Bird | Взмах, гравитация, границы, покачивание и падение | 5 |
| Ground | Повторение прокрутки и касание земли | 2 |
| PipePair | Геометрия прохода, общее движение, однократное прохождение и выход за экран | 4 |
| CollisionDetector | Земля, отсутствие препятствий, прозрачные и общие занятые пиксели | 4 |
| Game | Начало полёта, завершение и повтор после приземления | 3 |

В тестах Game технические зависимости заменяются `unittest.mock.Mock`: проверяются состояния раунда и запросы звуковых эффектов. Набор не проверяет реальное аудиоустройство, качество отрисовки или все возможные ошибки загрузки.

## Архитектура

Реализованы девять конкретных классов и три интерфейса.

| Класс | Ответственность |
|---|---|
| Bird | Состояние, движение и индекс кадра птицы |
| Ground | Уровень земли и циклическое смещение её изображения |
| PipePair | Верхняя и нижняя труба как одно препятствие |
| Game | Главный цикл, состояния раунда, счёт и координация объектов |
| CollisionDetector | Проверка столкновений по геометрии и логическим маскам |
| InputHandler | Перевод событий Pygame в команды `action` и `quit` |
| Renderer | Отображение состояния игры |
| SoundPlayer | Воспроизведение загруженных эффектов |
| AssetManager | Загрузка изображений, звуков и масок |

`IInputHandler`, `IRenderer` и `ISoundPlayer` задают небольшие контракты технических механизмов. Конкретные реализации создаются в `main.py` и передаются в Game через конструктор. Bird, Ground, PipePair, CollisionDetector и Game не импортируют Pygame.

Один кадр: получение команд → обработка команд → обновление состояния → отрисовка → ограничение частоты. Для трёх состояний (`welcome`, `playing`, `game_over`) используется обычное ветвление.

`HitMask = list[list[bool]]` описывает форму конкретного изображения. `True` соответствует пикселю с ненулевым альфа-каналом. После проверки прямоугольников алгоритм ищет общую экранную точку, занятую в обеих масках. Индексация сохранена из исходника: `mask[x][y]`.

## Изменения относительно исходника

В исходной версии функции одновременно обрабатывали ввод, движение, столкновения и вывод. Состояние передавалось через локальные переменные и словари, а ресурсы хранились глобально. После переработки данные принадлежат объектам, верхняя и нижняя трубы представлены одной парой, технические механизмы вынесены из правил игры.

Отдельно устранены пограничные случаи: прохождение пары учитывается один раз, создание следующей пары не зависит от попадания X в узкий диапазон. Шаг труб фиксирован как `-128 / 30` пикселя на кадр.

Движение остаётся покадровым при целевых 30 FPS. Маска птицы, как в исходной версии, не поворачивается вместе с изображением. Поэтому визуальный контур повёрнутой птицы может немного отличаться от области столкновения.
