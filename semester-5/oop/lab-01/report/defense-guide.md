## Ответ на вопрос, который ты не смог объяснить

**`const` ограничивает изменение через конкретный тип доступа или внутри метода. `&` в объявлении задаёт ссылку на существующий объект. Они решают разные задачи и могут стоять вместе.**

Например, `const MyString& other` — константная ссылка. `&` означает, что мы работаем с переданным объектом и не создаём его копию. `const` означает, что через имя `other` нельзя менять его содержимое обычными изменяющими методами. Сам исходный объект может быть неконстантным и изменяться через другое имя. Константная ссылка не «замораживает» все остальные ссылки на объект.

В записи `int compare(const MyString& other) const` последний `const` относится уже к текущему объекту, на котором вызвали метод. Для `a.compare(b)` параметр `other` обозначает `b`, а `this` обозначает `a`. Первый `const` защищает `b` через `other`, последний — ограничивает изменение `a` через `this`. Амперсанд связывает параметр с `b` без копирования.

Запомни правильный короткий ответ для преподавателя:

> «`const` — квалификатор, который ограничивает изменение. Ссылка `&` — способ обратиться к существующему объекту без создания копии. В `const MyString&` оба свойства сочетаются: копии нет, изменение через параметр запрещено. А `const` после скобок делает метод константным для текущего объекта».

Не отвечай «const — это строка», «ссылка — это копия», «const означает передать по ссылке», «ссылка в любом случае хранится как обычный указатель». Реализация хранения ссылки не является тем, что задаёт её смысл в языке.

## Разбор сигнатуры без пропусков

```cpp
const char& MyString::operator[](int index) const
```

`char` — тип одного элемента; `&` у результата — вернуть обозначение существующего элемента; левый `const` — запретить запись через возвращённую ссылку; `MyString::` — метод принадлежит классу; `operator[]` — перегруженная операция индексации; `int index` — индекс, переданный по значению; правый `const` — метод доступен на константном текущем объекте.

```cpp
MyString& MyString::operator+=(const char* source)
```

Здесь возвращается ссылка на текущий изменяемый объект. `const char*` — указатель, через который нельзя менять символы источника. В конце нет `const`, потому что `+=` изменяет строку. `return *this` разыменовывает указатель на текущий объект и возвращает его по ссылке.

```cpp
static_cast<void (MyString::*)(int, const char*)>(&MyString::insert)
```

Прочитай вслух: «Я выбираю указатель на метод класса MyString, который принимает int и const char*, возвращает void». `MyString::*` — указатель на член класса, а не обычный указатель на свободную функцию. `&MyString::insert` получает адрес нужного метода. `static_cast` задаёт его точный тип, чтобы компилятор выбрал одну из перегрузок. Внутри `def` метод сейчас не исполняется — регистрируется возможность вызвать его позже.

```python
from mystring import MyString

print(str(s))                            # aXYb!
```

## Вопросы преподавателя и ответы

### Const и ссылки

**1. Чем отличается const от &?** Const ограничивает изменение, & в объявлении задаёт ссылку. `const MyString&` сочетает ссылку без копирования и запрет изменения через этот параметр.

**2. Что делает const после скобок?** Делает нестатический метод константным для текущего объекта. Через this нельзя менять обычные поля и вызывать его изменяющие методы. Метод можно вызвать на const MyString.

**3. Почему compare содержит два const?** Один ограничивает параметр other, второй — текущий объект. Для a.compare(b) они относятся к разным объектам.

**4. Запрещает ли const-метод менять динамическую память?** Автоматически — нет. Const у объекта не превращает массив за char* в const-массив. Логическая константность требует, чтобы метод чтения не менял символы.

**5. Почему const char* c_str() const содержит два const?** Левый относится к символам через возвращённый указатель, правый — к методу и this. Это независимые ограничения.

**6. Чем const char* отличается от char* const?** В первом случае нельзя писать символ через указатель, но можно поменять сам указатель. Во втором нельзя поменять сам указатель, но символы через него менять можно. `const char* const` сочетает оба ограничения.

**7. Ссылка — отдельный объект строки?** Нет. Она обозначает исходный объект. В отличие от `MyString copy = original`, ссылка не запускает глубокое копирование.

**8. Можно ли перенаправить ссылку?** Нет. После инициализации `ref = other` присваивает содержимое объекту, с которым ref уже связана.

**9. Может ли ссылка быть null?** Корректная C++-ссылка предполагает существующий объект. Нельзя использовать ссылку как необязательный параметр с корректным нулевым состоянием; для этого обычно выбирают указатель или другой явный тип.

**10. Можно ли возвращать ссылку на локальную строку?** Нет. После выхода из функции она уничтожится, ссылка станет висячей. Поэтому substr возвращает новый объект по значению.

**11. Зачем operator[] возвращает char&?** Чтобы выражение s[i] обозначало настоящий элемент и присваивание изменяло массив. Возврат char по значению изменил бы лишь копию результата.

**12. Зачем const-перегрузка operator[]?** Чтобы читать const-объект и не дать запись через результат. Compare, объявленный const, использует именно эту перегрузку для текущего объекта.

**13. Const-ссылка делает исходную переменную const?** Нет. Ограничивает доступ через ссылку. Неконстантный исходный объект остаётся изменяемым через другие допустимые пути.

**14. Чем ссылка отличается от указателя?** Ссылка требует связывания при инициализации и не перенаправляется; указатель хранит значение адреса, может быть null и изменяться. Синтаксис доступа через ссылку похож на обычный объект. Не надо утверждать, что любая ссылка «ничего не занимает» в памяти.

**15. Что значит &MyString::size?** Это выражение получения указателя на метод, а не ссылочный параметр. Значение нужно библиотеке для последующего вызова на конкретном экземпляре.

### Класс и память

**16. Зачем три поля, нельзя считать strlen каждый раз?** Размер и ёмкость решают разные задачи. Хранение size делает геттер постоянным по времени; capacity показывает выделенный объём и обеспечивает правило его сохранения. Strlen не даёт ёмкость.

**17. Почему cat имеет capacity 4?** Три байта содержимого плюс завершающий нуль. Capacity этой лабы включает нуль.

**18. Почему у default capacity 0, а у MyString("") бывает 1?** Разные пути конструирования. Default не выделяет массив, конструктор C-строки выделяет size+1 даже для пустого литерала. Оба объекта empty.

**19. Кто освобождает c_str?** Никто снаружи. Это заимствованный указатель; массив освобождает деструктор MyString. Для пустого default это указатель на литерал, который также нельзя освобождать.

**20. Почему delete[]?** Память получена new char[]. Формы выделения и освобождения должны соответствовать. Delete без [] для массива — неверная пара.

**21. Зачем глубокое копирование?** Каждый объект должен владеть собственным массивом. Копирование только указателя создаёт риск изменения соседнего объекта и double free.

**22. Что такое правило трёх?** Для собственного ресурса надо согласовать деструктор, конструктор копирования и копирующее присваивание. У нас все три есть.

**23. Где move-конструктор?** Он не реализован. Это дополнительное задание. Не следует называть swap перемещающим конструктором.

**24. Почему clear не delete?** По контракту очищается содержимое и сохраняется capacity. Сжатие и освобождение пустого буфера выполняет shrink_to_fit.

**25. Зачем временная копия в присваивании?** Для источника внутри своей строки и для безопасной подготовки перед изменением. Она также даёт возможность выбрать сохранение буфера или обмен.

**26. Что было неверно в старом присваивании?** Безусловный swap с коротким temp уменьшал capacity. Теперь при достаточной ёмкости копируем в прежний массив и сохраняем объём.

**27. Значит при коротком присваивании new нет?** Нет. Массив назначения сохраняется, но temp создаётся и выделяет свой буфер. Это разные утверждения.

**28. Когда указатель c_str становится недействителен?** После уничтожения объекта и после операций, заменяющих массив. Вставка заменяет массив даже при достаточной capacity. Нельзя хранить старый указатель через такую операцию.

### Декомпозиция и методы

**29. Покажи переиспользование.** Открой append: он вызывает insert(size_, ...). Insert направляется в общую вставку. Затем покажи все сравнения, использующие compare, и find, использующий find_chars.

**30. Зачем insert_slice и insert_prefix?** Первый выбирает начало в источнике и проверяет s_index. Второй ограничивает число символов доступной длиной. Оба используют один алгоритм insert_chars.

**31. Почему индекс size допускается в insert, но не в []?** В конце можно вставить новый текст, но пользовательского символа с таким индексом ещё нет. Для [] допустимы 0..size-1.

**32. Что делают три цикла insert_chars?** Первый копирует префикс до index, второй источник, третий суффикс начиная с index и завершающий нуль. Новый массив становится полным до удаления старого.

**33. Почему s += s работает?** Источник остаётся в старом массиве, пока все части копируются в новый. Старый массив удаляется только в конце.

**34. Зачем временная строка в replace?** Источник может находиться в текущей строке. Нужно сохранить его до erase, иначе он сдвинется или потеряется.

**35. Есть ли у replace сильная гарантия исключений?** Нет. После erase вставка может не выделить память. Строка сохранит корректное состояние, но удалённый фрагмент не восстановится.

**36. Find вызывает find — это рекурсия?** Нет, здесь другая перегрузка с дополнительным параметром 0. Она далее вызывает find_chars. Это делегирование между перегрузками.

**37. Как устроен find_chars?** Внешний цикл перебирает начало совпадения, внутренний проверяет образец. Полное совпадение даёт индекс, отсутствие — -1. Пустой образец даёт стартовый индекс.

**38. Какая сложность поиска?** O(n·m) в худшем случае для наивного сравнения. Это не Ахо–Корасик и не КМП.

**39. Чем + отличается от +=?** + создаёт копию левого объекта, меняет копию и возвращает новый объект. += меняет левый объект и возвращает ссылку на него.

**40. Зачем unsigned char в compare?** Чтобы байты сравнивались в диапазоне неотрицательных значений независимо от того, знаковый ли char на данной платформе.

**41. Почему нельзя сразу привести отрицательный индекс к size_t?** Он превратится в большое беззнаковое число. Сначала проверяется отрицательность, потом выполняется приведение.

**42. Везде ли достигнуто отсутствие повторов?** Основные циклы изменения массива, поиска и сравнения централизованы. Небольшие адаптеры типов и три коротких operator+ имеют сходный шаблон. Я показываю конкретное вынесенное переиспользование и не утверждаю, что исходник не содержит вообще похожих строк.

### Граф

**43. Это граф или дерево?** Граф: одна функция может вызываться многими другими. Дерево требует более строгой структуры родителей; наши зависимости её не имеют.

**44. Куда направлена стрелка?** От метода, который вызывает, к методу, который вызывается. Append → insert означает, что append вызывает insert.

**45. Чем декомпозиция отличается от графа вызовов?** Декомпозиция — проектирование общих алгоритмов. Граф — фактические вызовы, извлечённые из IR. Их сравнение проверяет, совпал ли код с выбранной структурой.

**46. Что такое LLVM IR?** Промежуточное представление компилятора. Оно содержит функции, инструкции, вызовы и пути исключений; инструменты LLVM могут анализировать его до генерации машинного кода.

**47. Почему -O0?** Чтобы оптимизация меньше стирала границы методов и не встраивала основные вызовы. Это граф данной версии IR, а не универсальная структура любого оптимизированного бинарного файла.

**48. Что делает dot_unmangler?** Преобразует закодированные ABI-имена функций в читаемые подписи DOT. Он не придумывает рёбра и не заменяет построение графа инструментом opt.

**49. Почему 78, если в методичке 66?** В таблице номера и сигнатуры считаются по-разному. У присваивания три строковые формы в одном пункте, у сравнения шесть операторов, есть const [], а ещё шесть private-помощников. Всего 72 public и 6 private.

**50. Почему на рисунке 31 вершина?** Перегрузки объединены по имени в семейства. 78 — конкретные сигнатуры, 31 — имена семейств; это разные уровни детализации.

**51. Почему 106 связей превращаются в 41?** Повторные связи между одинаковыми семействами объединены; внутрисемейные переходы скрыты на укрупнённом рисунке. Полный DOT сохраняет их.

**52. Зачем конструктор и деструктор?** Код создаёт и очищает временные объекты. Деструктор может быть в обычном выходе или пути исключения. Граф не является только перечнем явно написанных вызовов в теле.

**53. Почему от конструктора пунктир к деструктору?** Это очистка объекта на пути исключения в делегирующем конструкторе. Не надо говорить, что каждый успешный конструктор немедленно уничтожает объект.

**54. Что за aliases и почему их раскрывали?** В IR отдельные ABI-символы конструкторов/деструктора являются псевдонимами реализации. Raw-граф пропустил часть связей. В промежуточной копии их сопоставили целям, проверили IR и сравнили итог с инструкциями исходного IR.

**55. Ты руками дорисовал стрелки?** Нет. Полный набор извлечён и независимо сверён. Для схемы проектирования связи выбирались вручную как упрощение, а граф вызовов основан на IR. После объединения перегрузок меняется представление, но не добавляются выдуманные вызовы.

**56. Где new, strlen и библиотека pybind11 на графе?** Библиотечные вызовы отфильтрованы из рисунка MyString. Pybind11 находится в другой единице трансляции. Граф класса не заявляется графом всей программы или интерпретатора.

### Обёртка и библиотека

**57. Что такое обёртка?** Адаптер между интерфейсами языков. Python-аргументы преобразуются к нужным C++-типам, вызывается исходный метод, результат или исключение возвращается в Python.

**58. Что находится в pyd?** Машинный код MyString и скомпилированных адаптеров pybind11, данные модуля и экспортируемая точка инициализации. Это бинарное расширение CPython, а не Python-исходник и не exe.

**59. Что делает PYBIND11_MODULE?** Создаёт точку инициализации модуля и код его регистрации. При import регистрируются класс и методы; пользовательские операции вызываются позже.

**60. Что происходит при import в версии 3.1.0?** CPython вызывает PyInit_mystring. Макрос возвращает определение модуля через PyModuleDef_Init; затем слот исполнения запускает регистрацию класса и методов. Это видно в detail/common.h.

**61. Что делает class_<MyString>?** Создаёт Python-тип и записывает сведения о соответствии C++-типу и его экземплярам. Без этой регистрации библиотека не знает, как получить MyString за Python self.

**62. Что делает def?** Создаёт или дополняет Python-метод. Для перегрузок ведётся цепочка. Внутри class_::def формируется cpp_function, содержащая адаптер конкретной C++-сигнатуры.

**63. Как метод реально вызывается внутри библиотеки?** Адаптер для указателя на метод получает Class* и выполняет `(c->*f)(args...)`. Dispatcher и type casters перед этим проверяют и преобразуют аргументы. Сам алгоритм обработки строки остаётся в MyString.cpp.

**64. Где это можно показать в библиотеке?** В установленном pybind11.h: обработчик member-function pointer, class_::def, создание PyMethodDef и dispatcher. В detail/common.h — макрос модуля; в cast.h — преобразования типов. Точные строки приведены ниже в справке.

**65. Как Python str становится const char*?** Библиотека получает UTF-8-представление, действительное на время вызова. Наш код копирует данные; он не сохраняет указатель на временный Python-аргумент.

**66. Почему не экспортированы все std::string-перегрузки?** Для Python они дублировали бы варианты str, и отдельного типа std::string там нет. C++-интерфейс сохранился, Python использует str и MyString.

**67. Чем выбор перегрузки в static_cast отличается от Python?** Static_cast выбирает конкретный C++-указатель при компиляции. Python-диспетчер выбирает одну из зарегистрированных привязок во время вызова по аргументам.

**68. Что такое type caster?** Шаблонный преобразователь, который загружает C++-значение из Python-объекта и создаёт Python-результат из C++-значения. Для зарегистрированного класса учитывается связь экземпляров и владение.

**69. Кто владеет C++-объектом из Python?** В используемой декларации class_ стандартный holder — unique_ptr<MyString>. Обёртка владеет C++-объектом; сам MyString владеет отдельным массивом data_. Это два уровня владения.

**70. Зачем reference_internal?** Возвращается ссылка на уже существующий self. Политика обозначает заимствование с привязкой времени жизни к родителю, чтобы не создавать неверное независимое владение.

**71. C_str в Python тоже висячий указатель?** Нет, наш привязанный результат преобразуется в отдельный Python str. В C++ c_str остаётся заимствованным указателем. Не путай два интерфейса.

**72. Почему assign вместо =?** Python a=b связывает имя с объектом и не вызывает C++ присваивание. Assign явно вызывает operator= у существующего объекта.

**73. Что делает __setitem__ lambda?** Проверяет одну ненулевую байтовую строку, получает self по ссылке и присваивает self[index]. Проверку индекса выполняет operator[] через check_index.

**74. Зачем is_operator?** Помечает привязку как Python-оператор. При неподходящем типе библиотека может вернуть NotImplemented, чтобы Python применил правила обратного оператора или сравнения; это не просто комментарий.

**75. Как исключение C++ оказывается в Python?** Адаптер библиотеки перехватывает исключение и ставит соответствующую ошибку CPython. Out_of_range становится IndexError, invalid_argument — ValueError. Наш Python ловит её try/except.

**76. Почему нужен тот же Python?** Бинарный модуль собран под конкретный ABI и зависимости. MSYS CLANG64 Python и обычный Windows Python даже с одинаковым номером версии могут иметь разные суффиксы и ABI.

**77. Как Python находит модуль?** По sys.path и допустимым суффиксам расширений. PYTHONPATH добавляет папку сборки к путям поиска. Имя модуля и PyInit_mystring должны согласовываться.

**78. Для чего GIL?** В обычном CPython он координирует исполнение и безопасную работу с API интерпретатора. В нашей привязке нет gil_scoped_release; операции не представлены как параллельные. Это не заменяет синхронизацию самого класса вне Python.

## Подробная теория и разбор архитектуры

### 4 Теоретические сведения

#### 4.1 Класс и объект

Класс описывает представление данных и операции над ними. Объект — конкретный экземпляр класса со своим состоянием. Например, после создания MyString a("cat") и MyString b("dog") у каждого объекта собственные поля и собственный массив символов. Метод a.size() читает размер объекта a, а b.size() — размер b.

Инкапсуляция выражается в том, что data_, size_ и capacity_ находятся в private. Пользователь класса вызывает public-методы, которые должны сохранять согласованность полей. Сам по себе private не защищает процесс от отладчика или повреждения памяти: это правило доступа на уровне языка, а не механизм изоляции операционной системы.

Конструктор создаёт начальное состояние и называется так же, как класс. У конструктора нет возвращаемого типа. Деструктор ~MyString завершает владение ресурсами объекта. Разные конструкторы имеют одинаковое имя, но отличаются параметрами; подходящий вариант определяется перегрузкой. Конструктор MyString(const MyString& other) в данном коде делегирует работу MyString(other.c_str()), то есть использует уже существующий конструктор из C-строки для глубокой копии.

```cpp
MyString::MyString(const MyString& other)
    : MyString(other.c_str()) {
}
```

Двоеточие здесь открывает список инициализации. В данном случае он содержит делегирование другому конструктору того же класса. Это не рекурсия: сигнатуры различаются, конструктор копирования передаёт const char* конструктору из C-строки.

#### 4.2 Константные методы

Константный метод — нестатический метод с const после списка параметров. В этой реализации к ним относятся size, capacity, empty, c_str, compare, find, substr, operator+ и чтение символа через const-перегрузку operator[]. Они доступны для константных объектов и обещают не изменять обычные поля объекта через this.

```cpp
int size() const;
int compare(const MyString& other) const;
const char& operator[](int index) const;
```

В const-методе выражение this имеет тип указателя на const MyString. Через него нельзя присвоить новое значение size_, capacity_ или data_, вызвать неконстантный clear либо append. Поля, объявленные mutable, были бы исключением; в MyString таких полей нет. Суффикс const входит в тип указателя на метод и влияет на выбор перегрузки. Например, чтение из const MyString выбирает const operator[].

При этом константность не является автоматически глубокой. Поле data_ имеет тип char*. Константность объекта запрещает заменить значение этого поля, но не превращает выделенный массив в массив const char. Изнутри const-метода технически возможна запись data_[0] = 'X'. Она нарушила бы логическую константность, хотя сама по себе такая запись через указатель не запрещена типом поля. Реализованные методы чтения этого не делают. Наружу c_str возвращает const char*, чтобы пользователь не изменял символы через данный интерфейс.

Для сравнения: const перед возвращаемым типом и const после параметров относятся к разным сущностям. В const char* c_str() const левый const запрещает изменение символов через возвращённый указатель, а правый const ограничивает работу метода с объектом. Метод, возвращающий const char*, без правого const всё ещё мог бы менять size_ или вызывать clear.

#### 4.3 Ссылки и различие между const и &

Ссылка в объявлении — другое имя уже существующего объекта. Запись MyString& ref = original связывает ref с original: операции через ref относятся к тому же объекту. Создание ссылки не вызывает конструктор копирования. Инициализированную ссылку нельзя перенаправить на другой объект; присваивание ref = another вызывает присваивание объекту original.

const — квалификатор типа или метода, ограничивающий изменение. Символ & в объявлении типа задаёт ссылку. Это независимые понятия, которые могут использоваться одновременно. В параметре const MyString& other ссылка позволяет передать существующий объект без копирования, а const запрещает изменить этот объект через other. Оригинал при этом не обязательно объявлен const: ограничение относится к этому пути доступа. Наличие других неконстантных ссылок на тот же объект не исключается.

| Запись | Копия объекта | Возможность изменения через параметр |
| --- | --- | --- |
| MyString value | Создаётся для передачи lvalue по значению | Можно изменить только параметр-копию |
| MyString& value | Нет | Можно изменить исходный объект |
| const MyString& value | Нет | Нельзя вызвать изменяющие методы через value |
| const MyString value | Создаётся для передачи lvalue по значению | Нельзя изменить параметр-копию |

Таблица описывает обычную передачу именованного объекта; для временных объектов возможны особенности устранения копирования. Ссылка должна оставаться связанной с живым объектом. Возврат ссылки на локальную переменную, уничтожаемую при выходе из функции, создаёт висячую ссылку.

В сигнатуре int compare(const MyString& other) const имеются три самостоятельных решения: int возвращается по значению; other передаётся как константная ссылка без копирования; конечный const делает метод константным для текущего объекта. Изменение other и изменение *this ограничиваются разными const. Ни один из них не означает, что результат compare должен быть константной переменной.

```cpp
MyString original("cat");
MyString& alias = original;
alias[0] = 'B';             // original теперь "Bat"
const MyString& view = original;
int length = view.size();   // допустимо
// view.clear();            // ошибка компиляции
// view[0] = 'X';           // ошибка компиляции
MyString copy = original;  // новый независимый объект
```

Символ & встречается и в других контекстах. В выражении &original это оператор получения адреса; в &MyString::append — получение указателя на метод; в MyString& — часть объявления ссылочного типа. Два амперсанда MyString&& задают rvalue-ссылку, связанную с move-семантикой. Конструктор перемещения в текущем коде не реализован.

#### 4.4 Ссылки в возвращаемом значении и время жизни

operator= и operator+= возвращают MyString& и в конце выполняют return *this. this — указатель на текущий объект, а *this — сам объект. Возвращается ссылка на продолжающий существовать левый операнд. Это позволяет использовать цепочки операций без создания дополнительной строки. Например, (a += "b") += "c" дважды изменяет a.

Неконстантный operator[] возвращает char&: выражение s[0] становится обозначением реального элемента массива, поэтому s[0] = 'X' изменяет строку. Константная перегрузка возвращает const char&, обеспечивая чтение без права записи через результат. У обеих перегрузок проверяется диапазон; доступ к завершающему нулю по индексу size() не разрешён.

c_str возвращает заимствованный указатель. Он не передаёт владение массивом вызывающему коду. После уничтожения строки этот указатель недействителен. Вставка в текущей реализации меняет массив даже при достаточной capacity, поэтому ранее полученные указатели и ссылки на символы могут стать недействительными. substr и operator+ возвращают объект по значению, который владеет своим массивом и не является видом на исходную строку.

#### 4.5 Перегрузки и явное приведение типов

Перегрузка позволяет одному имени обозначать несколько функций с разными наборами параметров. В insert перегрузки различаются типом источника и числом целочисленных параметров. Возвращаемого типа одного недостаточно, чтобы перегрузить функцию с теми же параметрами. Константность нестатического метода также участвует в различении const и non-const перегрузок.

static_cast<T>(expression) явно задаёт преобразование к типу T. В MyString.cpp он применяется для переходов между int и std::size_t после проверки диапазона и для представления символа как unsigned char при сравнении. Приведение не заменяет проверку: отрицательное int, преобразованное к size_t, может превратиться в большое положительное число. Поэтому отрицательный индекс проверяется до преобразования.

В обёртке static_cast используется иначе: он выбирает конкретный указатель из набора перегруженных методов. Например, static_cast<void (MyString::*)(const char*)>(&MyString::append) означает «указатель на нестатический метод MyString, принимающий const char* и возвращающий void». Сам метод при этом не вызывается. Эта запись нужна компилятору на этапе сборки привязки, а Python позднее выбирает среди зарегистрированных вариантов по аргументам.

#### 4.6 Владение памятью и исключения

Объект владеет массивом, полученным через new char[]. Освобождение производится через delete[], а не delete и не free. Копирование должно быть глубоким: копируются символы в другой массив. Копирование только значения data_ привело бы к совместному владению одним массивом, повреждениям при изменении и двойному освобождению.

Для класса с собственным ресурсом важны деструктор, конструктор копирования и копирующее присваивание — правило трёх. Эти операции реализованы. Правило пяти дополнительно рассматривает перемещение; такие специальные методы отсутствуют, и отчёт не приписывает классу поддержку move-семантики.

Неверный источник nullptr и отрицательное количество символов приводят к invalid_argument; недопустимый индекс — к out_of_range; непредставимый размер — к length_error. Отказ new при нехватке памяти может вызвать bad_alloc. Для C-строки всё равно существует предусловие: указатель должен вести к доступной последовательности, завершённой нулём. Проверка на nullptr не делает произвольный адрес безопасным и не доказывает корректность strlen для повреждённого указателя.



### 5 Представление строки

В MyString.h объявлены char* data_, int size_ и int capacity_. size_ считает хранимые элементы char без завершающего нуля. capacity_ считает выделенные элементы char вместе с местом под '\0'. Для обычного непустого объекта выполняются 0 ≤ size_ < capacity_ и data_[size_] == '\0'. Динамический массив принадлежит только одному объекту.

| Состояние | size | capacity | Данные |
| --- | --- | --- | --- |
| MyString() | 0 | 0 | data_ == nullptr, c_str() возвращает "" |
| MyString("cat") | 3 | 4 | c, a, t, '\0' |
| После clear у "cat" | 0 | 4 | Первый элемент '\0', массив сохранён |
| После shrink_to_fit пустой строки | 0 | 0 | Массив освобождён |
| MyString("") | 0 | 1 | Выделен массив из завершающего нуля |

Пустота не означает одинаковый объём выделенной памяти: объект после clear может хранить большой пустой буфер. c_str никогда не возвращает nullptr в штатном состоянии. Для объекта без массива он возвращает указатель на пустой строковый литерал. Пользователь не должен освобождать или модифицировать этот литерал.

Представление отличается от std::string: стандартный size считает элементы строки, а capacity характеризует возможность хранить элементы без включения завершающего нуля в пользовательский размер ёмкости. Поэтому результаты capacity нашего класса нельзя напрямую приравнивать к capacity std::string. Объект MyString не реализует small string optimization и не хранит короткие строки внутри своих полей.



### 6 Алгоритмическая декомпозиция и реализация методов

#### 6.1 Выделение общих операций

Декомпозиция построена от требуемых действий к общим алгоритмам. Добавление в конец является вставкой по индексу size_. Конкатенация использует добавление. Вставка префикса отличается от обычной вставки подготовкой количества, а вставка фрагмента — подготовкой начального адреса и длины. Поэтому для этих операций достаточно одного общего алгоритма изменения массива.

В private вынесены insert_chars, insert_prefix, insert_slice, check_index, find_chars и swap. В public также переиспользуются insert, append, erase, compare и конструкторы. Термин «базовый метод» здесь означает функцию, на алгоритме которой строятся другие операции; он не обязательно совпадает с первым методом в таблице задания.


Схема является упрощённой: она показывает общий алгоритм и главные зависимости, а не все вызовы c_str, конструкторов и деструктора. В оригинальном MyString_decomposition.drawio имеются отдельные страницы для основной цепочки, вариантов insert и остальных помощников. Функций с именами memcopy и MakeRoom в данном коде нет: выделение памяти и копирование трёх частей находятся непосредственно в insert_chars.

#### 6.2 Конструкторы и деструктор

Конструктор по умолчанию задаёт data_ = nullptr, size_ = 0, capacity_ = 0. Конструктор из const char* сначала создаёт это безопасное состояние, проверяет указатель, вычисляет strlen, проверяет представимость длины и выделяет size_ + 1 символов. Затем циклом копирует символы и явно записывает завершающий нуль.

Конструкторы из std::string и MyString передают source.c_str() конструктору из C-строки. Конструкторы с count ограничивают количество доступной длиной источника: просьба скопировать больше имеющихся символов приводит к копированию только имеющихся. Отрицательный count отклоняется. Конструктор повторения выделяет count + 1 элементов, заполняет первые count символом ch и добавляет нуль. При count == 0 он оставляет состояние конструктора по умолчанию.

Деструктор вызывает delete[] data_. Освобождение nullptr допустимо. Размер массива не требуется передавать delete[] вручную. Деструктор освобождает принадлежащую объекту память, но не уничтожает внешние исходные строки.

#### 6.3 Геттеры и операции с ёмкостью

size, capacity и empty читают поля за постоянное время. c_str возвращает data_, а при отсутствии массива — пустой литерал. clear обнуляет size_ и первый символ, сохраняя capacity_. Эта операция не проходит по всему массиву: остаток прежних байтов за новым концом строки не очищается. Поэтому clear не следует считать безопасным стиранием конфиденциальных данных.

shrink_to_fit — единственная операция намеренного уменьшения ёмкости. Если строка пуста, массив освобождается и поля переводятся в нулевое состояние. Если ёмкость уже равна size_ + 1, работа не требуется. Иначе выделяется новый точный массив, копируются символы вместе с нулём, затем освобождается старый. Сначала new, затем delete сохраняет прежнее состояние при отказе выделения памяти.

#### 6.4 Присваивание и исправление capacity

Присваивание из const char* сначала создаёт независимый временный объект temp. Это защищает случаи s = s.c_str() и s = s.c_str() + 1: источник сохраняется до любых изменений текущего массива. Если capacity_ достаточна для temp.size_ + 1, символы вместе с нулём копируются в прежний массив, меняется только size_. Если места недостаточно, swap обменивает состояния; деструктор temp затем освобождает прежний массив текущего объекта.

```cpp
MyString& MyString::operator=(const char* source) {
    MyString temp(source);
    if (capacity_ >= temp.size_ + 1) {
        for (int i = 0; i <= temp.size_; ++i) {
            data_[i] = temp.data_[i];
        }
        size_ = temp.size_;
    } else {
        swap(temp);
    }
    return *this;
}
```

Без условия достаточности ёмкости безусловный обмен с коротким temp уменьшал бы capacity и нарушал условие лабораторной. Исправление сохраняет уже выделенный объём. Проверка с большой строкой и последующим присваиванием короткой включена в тестирование. Важно различать сохранение массива назначения и отсутствие любых выделений: temp всё равно создаёт свой массив.

Строковые operator= из std::string и MyString делегируют варианту const char*. Присваивание char создаёт локальный массив из символа и завершающего нуля, затем также вызывает строковое присваивание. swap вручную обменивает указатель, размер и ёмкость, не копируя символы. Возвращаемая ссылка позволяет выполнить a = b = "cat".

#### 6.5 Общая вставка insert_chars

Функция проверяет индекс в диапазоне [0, size_], количество символов и источник. Индекс size_ допустим: это вставка в конец. При count == 0 после проверки аргументов изменение не требуется. До вычисления size_ + count проверяется, не превышен ли предел int с учётом одного элемента для '\0'.

Новый размер равен старому размеру плюс count. Новая ёмкость выбирается как максимум прежней capacity_ и нового размера плюс один. Выделяется новый массив. В него последовательно копируются префикс [0, index), вставляемый фрагмент [0, count) и старый суффикс [index, size_] вместе с нулём. Только после завершения всех трёх циклов удаляется старый массив и обновляются поля.

Для примера "ab" с вставкой "XY" по индексу 1 префикс равен "a", источник — "XY", суффикс — "b\0". После копирования получается "aXYb", size == 4. Исходный массив остаётся доступным на время копирования, поэтому вставка своей строки в себя безопасна относительно перекрывающихся источников.

Вставка всегда выделяет новый массив, даже если ёмкости достаточно. Это простой способ обеспечить корректность при источнике из той же строки. Цена решения — дополнительные выделения и линейное копирование. Время O(n + k), где n — исходная длина, k — число вставляемых символов. Повторное добавление по одному символу без геометрического роста приводит к квадратичным суммарным затратам.

#### 6.6 Перегрузки insert и append

Обычный insert из const char* вычисляет strlen и передаёт данные insert_chars. Вариант std::string передаёт data() и size(), а вариант MyString — c_str() и size(). Вставка count повторяющихся символов сначала создаёт временный MyString(count, ch), затем использует общий алгоритм.

insert_prefix ограничивает count доступной длиной источника и вызывает insert_chars. Сужающее преобразование available в int выполняется только в ветке available < count, где count уже неотрицателен и помещается в int. insert_slice проверяет s_index в источнике, вычисляет source + s_index и оставшуюся длину, затем вызывает insert_prefix. Благодаря этому одна реализация обслуживает префиксы и фрагменты всех трёх типов источника.

Все десять append выполняют соответствующий insert(size_, ...). В append не дублируются проверки размера, выделение массива или циклы копирования. Операторы += опираются на append. На схеме следующие связи показаны непосредственно из графа вызовов; вызовы подготовки временных объектов здесь опущены.


#### 6.7 Удаление erase и замена replace

erase принимает начальный индекс и число удаляемых символов. Индекс может быть равен size_: удалять в конце нечего. Отрицательный count отклоняется. Количество ограничивается остатком size_ - index. Суффикс сдвигается влево циклом, который включает завершающий нуль; size_ уменьшается, capacity_ остаётся прежней. Копирование слева направо безопасно, поскольку назначение находится левее читаемого источника.

Основной replace сначала создаёт независимую строку replacement, затем выполняет erase и insert. Вариант с ограниченным количеством создаёт replacement(source, s_count), а вариант с фрагментом готовит fragment через append(source, s_index, s_count). Перегрузки std::string и MyString направляются к варианту const char*.

Временный объект нужен до erase, поскольку источник может указывать внутрь текущего массива. После сохранения источника удаление его не разрушит. Однако вся операция replace не имеет сильной гарантии исключений: если erase завершился, а последующая вставка вызвала bad_alloc, строка останется уже с удалённым участком. Объект при этом сохраняет корректное владение памятью. Это ограничение выбранной композиции, которое нельзя скрыть утверждением о безусловном откате любой операции.

#### 6.8 Подстрока и конкатенация

substr(index) проверяет индекс и вызывает substr(index, size_ - index). Второй вариант создаёт MyString(c_str() + index, count). Результат — независимый объект. Изменение исходной строки не меняет выделенную подстроку. Индекс size_ разрешён и даёт пустой результат; отрицательные индексы запрещены.

Три operator+ создают result как копию текущего объекта, вызывают result.append(source), затем возвращают result по значению. Левый операнд не изменяется; поэтому operator+ объявлен const. Три operator+= изменяют текущий объект через append и возвращают ссылку на него. Повторение нескольких строк в коротких operator+ — небольшой общий шаблон, но основной алгоритм копирования и изменения массива вынесен в конструктор и append; дополнительных циклов там нет.

#### 6.9 Индексация и сравнение

check_index проверяет 0 ≤ index < size_. Обе перегрузки operator[] используют эту функцию и возвращают ссылку на data_[index]. Const-перегрузка нужна для чтения из const MyString, в частности внутри compare. Проверка отличается от индекса вставки: символа с индексом size_ в пользовательской строке нет.

compare определяет длину общего префикса, читает пары символов через operator[], преобразует их к unsigned char и возвращает -1 или 1 при первом различии. Если общий префикс совпал, меньшей считается более короткая строка. При одинаковом содержимом возвращается 0. Все шесть операторов сравнения проверяют знак одного результата compare, что исключает шесть отдельных алгоритмов сравнения.


#### 6.10 Поиск find

Три find без индекса вызывают соответствующие перегрузки find(source, 0). Это вызов другой перегрузки, а не рекурсивный вызов с неизменными параметрами. Перегрузки с индексом подготавливают адрес и длину источника и передают их find_chars.

find_chars проверяет начало поиска, принимает пустой образец как совпадение в start и возвращает -1, если образец длиннее доступного суффикса. Далее внешний цикл выбирает возможную позицию начала, внутренний сравнивает символы. При первом различии внутренняя проверка прерывается; при полном совпадении возвращается индекс. Когда все позиции исчерпаны, результат -1. Это простой поиск последовательным сравнением, со сложностью O(n · m) в худшем случае. Алгоритм Ахо–Корасика относится к дополнительному заданию и не реализован.



### 7 Построение и анализ графа вызовов

#### 7.1 Декомпозиция и фактический граф

Алгоритмическая декомпозиция описывает выбранную структуру решения: какие общие операции выделены и как на них строятся остальные. Граф вызовов извлекается из скомпилированного представления и показывает фактические зависимости. Сопоставление необходимо, чтобы подтвердить переиспользование и увидеть дополнительные связи с временными объектами и проверками.

Вершина полного графа — конкретная сигнатура метода; направленное ребро A → B означает, что код A содержит прямой вызов B. Это не порядок всех действий программы и не число запусков функции. Наличие ребра не означает, что вызов выполнится для каждого набора данных: например, swap в присваивании вызывается только при нехватке места. Граф также не является деревом, поскольку к одному помощнику ведут несколько вызывающих методов.

#### 7.2 Получение LLVM IR и преобразование имён

Для MyString.cpp получено промежуточное представление LLVM IR без оптимизации. Clang переводит C++ в IR, которое затем может анализироваться и оптимизироваться инструментами LLVM до генерации машинного кода. Использование -O0 сохраняет отдельные функции и вызовы, которые при встраивании на -O2 или -O3 могли бы исчезнуть как самостоятельные рёбра [8, 9].

```text
clang++ -std=c++17 -O0 -S -emit-llvm MyString.cpp -o MyString.ll
opt -passes=dot-callgraph -disable-output MyString.ll
```

Флаг -S совместно с -emit-llvm даёт текстовый IR, а не ассемблерный файл машинной архитектуры. В IR присутствуют инструкции call и invoke: invoke имеет также путь перехода при исключении. opt выводит граф в DOT. В исходном DOT имена C++ закодированы по правилам ABI. Предоставленный курсом dot_unmangler.py и llvm-cxxfilt преобразуют эти имена в читаемые сигнатуры. Деманглирование меняет подписи, но само по себе не определяет структуру вызовов.

В итоговый рисунок оставлены только методы MyString. Вызовы strlen, new/delete, std::string, стандартных обработчиков исключений и LLVM intrinsics исключены из рисунка класса. Это фильтрация для анализа собственного интерфейса; такие библиотечные операции по-прежнему выполняются программой. Python-обёртка компилируется из отдельного файла и не включается в этот граф.

#### 7.3 Псевдонимы конструкторов в IR

В используемом IR обнаружены девять aliases — псевдонимов символов конструкторов и деструктора. Некоторые вызовы направлены к псевдониму C1, который ссылается на реализацию C2. Первоначальный граф opt не сопоставил все эти связи с конкретными методами: после фильтрации было видно 89 внутренних рёбер. Одно деманглирование не устраняет такой пропуск.

Для анализа создана промежуточная копия IR, в которой ссылки на псевдонимы в местах вызовов сопоставлены с целевыми символами. Исходник MyString.cpp не изменялся. Копия проверена проходом verify, после чего повторён dot-callgraph. Независимая проверка инструкций call/invoke исходного IR с раскрытием aliases дала тот же набор из 106 внутренних рёбер. Это позволяет отличить реально извлечённый граф от вручную нарисованной схемы.

#### 7.4 Итоговые представления

Полный MyString_methods.dot содержит 78 сигнатур и 106 различных прямых связей. Для читаемого рисунка перегрузки объединены по имени в 31 семейство; после объединения остаётся 41 различная связь между семействами. Внутрисемейные переходы скрыты только на укрупнённом рисунке: например, find(source) → find(source, 0) и substr(index) → substr(index, count). В полном DOT эти переходы сохранены.

Конструкторы и деструктор оставлены в графе. Они участвуют в подготовке, возврате и очистке временных строк. Пунктир от семейства конструкторов к деструктору относится к сгенерированной очистке при исключении в делегирующем конструкторе; он не означает, что каждый успешный конструктор сразу уничтожает создаваемый объект.


Обзор показывает весь набор зависимостей. Для чтения подписей служат увеличенные части в приложении и векторный файл graphs/MyString_families.svg; отдельные ключевые цепочки приведены на рисунках 2–4. В draw.io доступны редактируемые блоки, но ручное перемещение блоков не изменяет полученные из IR связи.

Сопоставление с декомпозицией подтвердило цепочку operator+ / operator+= → append → insert → insert_chars и вспомогательные пути через insert_slice и insert_prefix. Все операторы сравнения направлены к compare, а далее к const operator[] и check_index. Find использует find_chars. Replace переиспользует erase и insert, а вариант с фрагментом вызывает append при подготовке временного источника. Дополнительные связи с c_str, size, конструкторами и деструктором объясняют, почему фактический граф подробнее схемы проектирования.



### 8 Создание Python обёртки

#### 8.1 Выбор способа связывания

Для обращения Python к C++ можно вручную написать расширение CPython C API, использовать генератор SWIG либо библиотеку pybind11. Прямой C API требует самостоятельно описывать Python-типы, разбирать аргументы, преобразовывать результаты и учитывать счётчики ссылок. SWIG генерирует привязки по описанию интерфейса. Pybind11 позволяет задавать связь через C++-шаблоны и указатели на функции и методы.

В данной работе используется pybind11: это соответствует приложенному тесту обёртки и позволяет явно перечислить доступные конструкторы и перегрузки. Вызовы методов выполняются в исходном MyString; алгоритмы обработки строки на Python не переписываются. ctypes с C-интерфейсом потребовал бы отдельного набора экспортируемых C-функций и дескрипторов объектов: он не подключает произвольный C++-класс напрямую.

#### 8.2 Модуль и регистрация класса

```cpp
namespace py = pybind11;
PYBIND11_MODULE(mystring, m) {
    py::class_<MyString> cls(m, "MyString");
    cls.def(py::init<>());
    cls.def(py::init<const char*>());
    cls.def("size", &MyString::size);
}
```

namespace py — короткое имя пространства pybind11. Макрос PYBIND11_MODULE задаёт имя mystring и код регистрации. При сборке на Windows получается .pyd — загружаемая библиотека расширения CPython. Она не является обычной программой с main и не запускается кнопкой Run как executable.

При import Python ищет модуль в путях импорта, загружает библиотеку и вызывает экспортируемую точку PyInit_mystring. В установленной pybind11 3.1.0 макрос создаёт PyModuleDef_Init и слот исполнения модуля, который вызывает пользовательский код регистрации. Во время регистрации создаётся Python-тип MyString, добавляются конструкторы и методы; при этом операции append, find или erase над пользовательскими строками ещё не выполняются [2, 7].

py::class_<MyString> связывает Python-тип с конкретным C++-типом. def(py::init<...>()) регистрирует конструктор с указанными типами параметров. def("size", &MyString::size) регистрирует метод чтения размера. Это декларация связи, а не текущий вызов size. Приватные поля напрямую не экспортируются.

#### 8.3 Что происходит внутри pybind11

Для проверки механизма рассмотрены установленные заголовки pybind11, в частности pybind11.h, detail/common.h, cast.h и detail/type_caster_base.h. Это существенно: библиотека не просто хранит строку с именем метода. Шаблоны при компиляции формируют адаптер для конкретной C++-сигнатуры, а во время регистрации создают структуры, которые может вызывать интерпретатор.

В cpp_function обработчик указателя на метод формирует функцию, которая получает Class* c и вызывает (c->*f)(args...). Для const-метода используется const Class*. def связывает такую cpp_function с Python-именем. Библиотека подготавливает function_record с описанием вызова и PyMethodDef для взаимодействия с CPython. Диспетчер получает Python-аргументы, выбирает зарегистрированный вариант, выполняет load_args через type casters и вызывает подготовленный C++-адаптер. Возвращаемое значение преобразуется обратно в объект Python.

Вызов s.append("!") проходит следующие стадии: Python передаёт s и строку аргумента; pybind11 находит вариант append(const char*); получает C++-объект за self и представление аргумента; вызывает исходный MyString::append; тот вызывает insert и insert_chars. C++-метод void превращается в Python-результат None. При исключении обычный возврат заменяется механизмом трансляции ошибки.


Объект Python содержит служебную информацию и связь с экземпляром C++, а не только массив символов строки. MyString отдельно владеет data_. В текущей декларации не указан специальный holder; обычный default holder pybind11 имеет тип std::unique_ptr<MyString>. При окончательном уничтожении владеющей обёртки уничтожается C++-объект, и его деструктор освобождает массив. Настраиваемые режимы holder библиотеки не означают, что они автоматически применены в этой лабораторной [6].

#### 8.4 Преобразование аргументов

Python str для перегрузок const char* преобразуется к UTF-8-представлению, действительному на время вызова. Конструктор и методы MyString копируют нужные байты, поэтому не сохраняют указатель на временные данные Python. Аргумент Python MyString распознаётся как экземпляр зарегистрированного типа и передаётся исходной функции по ссылке. Для int и char используются соответствующие преобразования и проверки библиотеки [4, 5].

В Python нет отдельного типа std::string, поэтому одинаковые по смыслу строковые перегрузки C++ не дублируются в привязках: str передаётся в const char*, экземпляр MyString — в const MyString&. Это уменьшает неоднозначность выбора. На уровне C++ все три типа SOURCE_STR сохранены.

Текущий класс работает с байтами char. Для строки из ASCII каждый символ занимает один байт, но символ UTF-8 может занимать несколько. Поэтому size и индексация не реализуют операции над Unicode-кодовыми точками. Чтение одиночного char через библиотеку не эквивалентно выделению целого многобайтового символа. Для воспроизводимой демонстрации используются ASCII-строки.

#### 8.5 Перегрузки в обёртке

```cpp
cls.def("append",
    static_cast<void (MyString::*)(const char*)>(&MyString::append));
cls.def("append",
    static_cast<void (MyString::*)(const MyString&)>(&MyString::append));
```

На этапе компиляции запись &MyString::append неоднозначна, потому что имеется десять перегрузок. Явный тип указателя на метод выбирает конкретную сигнатуру. В другом примере static_cast<MyString (MyString::*)(int) const> задаёт возвращаемый объект, целочисленный параметр и константность метода substr.

На этапе выполнения одинаковое Python-имя append имеет несколько зарегистрированных вариантов. Диспетчер пробует подходящие варианты по числу аргументов и возможности преобразовать их типы; точное поведение включает проход без дополнительных преобразований и проход с ними. В этом файле нет py::arg с именами параметров, поэтому демонстрация использует позиционные аргументы. Не следует обещать вызовы с произвольными ключевыми именами.

#### 8.6 Результаты и время жизни

size, capacity и find возвращают Python int, empty и сравнения — bool, void-методы — None. c_str и __str__ дают Python str: библиотека создаёт строку из возвращённых байтов, поэтому Python-результат не является долговременным заимствованием массива data_. substr и operator+ дают новый MyString, который владеет самостоятельным C++-объектом.

operator= и operator+= возвращают MyString& на текущий объект. Для этих методов явно задана return_value_policy::reference_internal: результат рассматривается как ссылка, связанная с временем жизни родительского объекта. Это предотвращает ошибочное присвоение отдельного владения уже существующему self. В проверках target.assign("new") is target подтверждает возврат того же Python-объекта [3].

В Python a = b меняет привязку имени a к объекту b и не вызывает C++ operator=. Поэтому для изменения содержимого существующего объекта экспортированы assign и assign_char. В свою очередь a += b вызывает __iadd__, который направляется к operator+= и возвращает self. Оператор + направляется к __add__ и возвращает новый объект.

#### 8.7 Индексация и исключения

__getitem__ связан с const operator[]. Результат char преобразуется в Python-строку длиной одного символа соответствующего представления библиотеки. __setitem__ реализован небольшой lambda-функцией: она принимает self по MyString&, индекс и std::string value; проверяет, что value содержит ровно один ненулевой байт, затем выполняет self[index] = value[0]. Захват [] пуст, лямбда не использует внешние переменные.

Эта проверка запрещает пустую строку, несколько байтов и '\0' при записи из Python. Граница индекса остаётся в check_index. Отрицательная индексация, привычная для Python-списка, специально не добавлена: для MyString она приводит к IndexError.

Стандартные исключения C++ pybind11 переводит в ошибки Python: out_of_range — IndexError, invalid_argument и length_error — ValueError, bad_alloc — MemoryError. Неподходящий набор аргументов функции обычно приводит к TypeError. В коде не нужно вручную перехватывать каждое исключение и возвращать фиктивное значение; пользователь Python обрабатывает ошибку через try/except [10].

#### 8.8 Сборка и совместимость интерпретатора

Локальный файл модуля имеет имя mystring.cp314-mingw_x86_64_ucrt_llvm.pyd. Суффикс отражает используемый ABI и среду. Для запуска выбран C:\Users\chere\msys64\clang64\bin\python.exe — тот же интерпретатор, с которым выполнялась сборка. Совпадение номера 3.14 у обычного Windows Python само по себе не гарантирует совместимость с модулем MinGW/CLANG64.

Для импорта папка сборки должна быть в sys.path, например через PYTHONPATH. Необходимо различать ошибку отсутствия модуля и ошибку загрузки зависимой DLL. Установка произвольного пакета mystring из PyPI не исправляет путь к собственному собранному модулю. Пересборка C++-модуля выполняется CMake; import не компилирует исходники заново.

Обёртка не содержит явного освобождения GIL. Обычные обращения к Python и вызовы привязок в используемой конфигурации выполняются при удержании GIL. Это не делает сам C++-класс потокобезопасным при произвольном доступе из нескольких C++-потоков и не означает проверенную совместимость с free-threaded Python.

Запрошенная преподавателем теоретическая справка дополнена разделами о const methods и references. В них разделены константность текущего объекта, константность параметра, ссылка на существующий объект и возвращаемая ссылка. Существуют ограничения, не обнаруженные обычными ASCII-сценариями автотеста. Запись s[1] = '\0' разрешена C++-ссылочным интерфейсом: у "abc" после неё size() остаётся 3, а strlen(c_str()) даёт 1. Строки со встроенным нулём обрабатываются неодинаково: конструктор из std::string делегирует C-строке и обрезает данные по нулю, тогда как append(std::string) использует data() и size() и может вставить все байты. Временная проверка std::string("a\0b", 3) дала размер 1 после конструктора и размер 3 после append. Полноценный бинарный строковый контракт не заявляется.

Тесты для нормального ASCII-текста пройдены, для произвольных UTF-8 и бинарных последовательностей полноценная совместимость не подтверждена.

После изменения массива полученные ранее c_str и char& могут стать недействительными. Класс не предназначен для совместного изменяющего доступа без синхронизации, не хранит строку в защищённой памяти и не стирает остаточные байты при clear. ### Функция 15 — `void MyString::shrink_to_fit()`

Пункт методички: **11**. Место: `MyString.cpp:136`.

Для пустой строки освобождает массив и обнуляет поля. Для уже точной ёмкости ничего не делает. Иначе выделяет size_+1, копирует до i<=size_ включительно и лишь затем удаляет старый буфер. Это единственный разрешённый способ уменьшить capacity.

```cpp
void MyString::shrink_to_fit() {
    if (size_==0) {
        delete[] data_;
        data_ = nullptr;
        capacity_ = 0;
        return;
    }
    if (capacity_==size_+1) {
        return;
    }
    char* new_data = new char[size_+1];
    for (int i=0; i<=size_;++i) {
        new_data[i]=data_[i];
    }
    delete[] data_;
    data_ = new_data;
    capacity_=size_+1;
}
```

```cpp
    if (count < 0 || (count > 0 && source == nullptr)) {
        throw std::invalid_argument("invalid source or count");
    }
    if (count == 0) {
        return;
    }
    if (count > std::numeric_limits<int>::max() - 1 - size_) {
        throw std::length_error("string is too long");
    }

    int new_size = size_ + count;
    int new_capacity = capacity_;
    if (new_capacity < new_size + 1) {
        new_capacity = new_size + 1;
    }

    char* new_data = new char[new_capacity];
    const char* old_data = c_str();

    for (int i = 0; i < index; ++i) {
        new_data[i] = old_data[i];
    }
    for (int i = 0; i < count; ++i) {
        new_data[index + i] = source[i];
    }
    for (int i = index; i <= size_; ++i) {
        new_data[i + count] = old_data[i];
    }

    delete[] data_;
    data_ = new_data;
    size_ = new_size;
    capacity_ = new_capacity;
}
```

### Функция 44 — `void MyString::erase (int index, int count)`

Пункт методички: **38**. Место: `MyString.cpp:377`.

Проверяет индекс и count, ограничивает count остатком строки. Цикл сдвигает хвост влево, включая нуль. После цикла уменьшается только size_. Ёмкость и массив сохраняются. При count==0 — ранний выход.

```cpp
void MyString::erase (int index, int count) {
    if (index < 0 || index >size_) {
        throw std::out_of_range("invalid index");
    }
    if (count < 0) {
        throw std::invalid_argument("negative count");
    }
// Clamp count to the number of remaining characters.
    if (count > size_ - index) {
        count = size_ - index;
    }
    if (count ==0) {
        return;
    }
    // Shift the suffix left, including the terminating null character.
    for (int i=index; i+count <=size_;++i) {
        data_[i]=data_[i+count];
    }
    size_ -= count;
}
```

### Функция 65 — `int MyString::compare(const MyString& other) const`

Пункт методички: **57**. Место: `MyString.cpp:518`.

Принимает второй объект по const-ссылке и сам объявлен const. Сравнивает общий префикс через const [], приводит символы к unsigned char. При различии возвращает -1/1, иначе сравнивает размеры. Возвращает значение, не ссылку. O(min(n,m)).

```cpp
int MyString::compare(const MyString& other) const {
    int common_size = size_;
    if (other.size_ < common_size) {
        common_size = other.size_;
    }
    for (int i=0; i<common_size; ++i) {
        unsigned char left = static_cast<unsigned char>((*this)[i]);
        unsigned char right = static_cast<unsigned char>(other[i]);

        if (left < right) {
            return -1;
        }
        if (left > right) {
            return 1;
        }
    }

    if (size_ < other.size_ ) {
        return -1;
    }
    if (size_ > other.size_) {
        return 1;
    }
    return 0;
}
```

### Функция 72 — `int MyString::find_chars(const char* source, std::size_t length, int start) const`

Пункт методички: **private**. Место: `MyString.cpp:570`.

Проверяет start в 0..size и источник. Пустой образец возвращает start. Слишком длинный — -1. Внешний цикл выбирает i, внутренний j сравнивает образец. Первый полный успех возвращает int-индекс, исчерпание — -1. Это наивный поиск, O(n*m).

```cpp
int MyString::find_chars(const char* source,
                         std::size_t length, int start) const {
    if (start < 0 || start > size_) {
        throw std::out_of_range("invalid start index");
    }
    if (source == nullptr) {
        throw std::invalid_argument("source is null");
    }
    if (length == 0) {
        return start;
    }

    std::size_t available = static_cast<std::size_t>(size_ - start);
    if (length > available) {
        return -1;
    }

    const char* text = c_str();

    for (std::size_t i = static_cast<std::size_t>(start);
         i + length <= static_cast<std::size_t>(size_);
         ++i) {
        bool same = true;

        for (std::size_t j = 0; j < length; ++j) {
            if (text[i + j] != source[j]) {
                same = false;
                break;
            }
        }

        if (same) {
            return static_cast<int>(i);
        }
         }

    return -1;
}
```

## Полный файл привязок для сопоставления

Ниже именно текущий код. После регистрации каждой группы открой соответствующий метод в MyString.cpp и пройди цепочку до общей функции.

```cpp
#include <pybind11/pybind11.h>
#include <stdexcept>
#include <string>
#include "MyString.h"

namespace py = pybind11;

PYBIND11_MODULE(mystring, m) {
    // При импорте регистрируем связи с C++ методами. Сами методы вызываются позже.
    py::class_<MyString> cls(m, "MyString");

    // Python str передаем в перегрузки const char*, а Python MyString — в const MyString&.
    // Перегрузки со std::string не дублируем: отдельного типа std::string в Python нет.
    cls.def(py::init<>());
    cls.def(py::init<const char*>());
    cls.def(py::init<const char*, int>());
    cls.def(py::init<int, char>());
    cls.def(py::init<const MyString&>());       // Конструктор копирования -> MyString(const char*).
    cls.def(py::init<const MyString&, int>());

    // Геттеры читают тот же объект. Для c_str() pybind11 создает Python str.
    cls.def("c_str", &MyString::c_str);
    cls.def("__str__", &MyString::c_str);
    cls.def("size", &MyString::size);
    cls.def("__len__", &MyString::size);
    cls.def("capacity", &MyString::capacity);
    cls.def("empty", &MyString::empty);
    cls.def("clear", &MyString::clear);
    cls.def("shrink_to_fit", &MyString::shrink_to_fit);

    // В Python a = b меняет ссылку a. Чтобы вызвать C++ operator=, есть assign().
    // Результат operator= — ссылка на self, поэтому сохраняем связь с его временем жизни.
    cls.def("assign", static_cast<MyString& (MyString::*)(const char*)>(&MyString::operator=),
            py::return_value_policy::reference_internal);
    cls.def("assign", static_cast<MyString& (MyString::*)(const MyString&)>(&MyString::operator=),
            py::return_value_policy::reference_internal);
    cls.def("assign_char", static_cast<MyString& (MyString::*)(char)>(&MyString::operator=),
            py::return_value_policy::reference_internal);

    // static_cast выбирает перегрузку при сборке. При вызове Python выбирает подходящую из них.
    // insert(index, count, ch) -> временный MyString -> insert_chars().
    cls.def("insert", static_cast<void (MyString::*)(int, int, char)>(&MyString::insert));
    // insert(index, source) -> insert_chars().
    cls.def("insert", static_cast<void (MyString::*)(int, const char*)>(&MyString::insert));
    cls.def("insert", static_cast<void (MyString::*)(int, const MyString&)>(&MyString::insert));
    // Вставка префикса -> insert_prefix() -> insert_chars().
    cls.def("insert", static_cast<void (MyString::*)(int, const char*, int)>(&MyString::insert));
    cls.def("insert", static_cast<void (MyString::*)(int, const MyString&, int)>(&MyString::insert));
    // Вставка фрагмента -> insert_slice() -> insert_prefix() -> insert_chars().
    cls.def("insert", static_cast<void (MyString::*)(int, const char*, int, int)>(&MyString::insert));
    cls.def("insert", static_cast<void (MyString::*)(int, const MyString&, int, int)>(&MyString::insert));

    // append() вызывает соответствующий insert(size_, ...), поэтому общая работа в insert_chars().
    cls.def("append", static_cast<void (MyString::*)(int, char)>(&MyString::append));
    cls.def("append", static_cast<void (MyString::*)(const char*)>(&MyString::append));
    cls.def("append", static_cast<void (MyString::*)(const MyString&)>(&MyString::append));
    cls.def("append", static_cast<void (MyString::*)(const char*, int)>(&MyString::append));
    cls.def("append", static_cast<void (MyString::*)(const MyString&, int)>(&MyString::append));
    cls.def("append", static_cast<void (MyString::*)(const char*, int, int)>(&MyString::append));
    cls.def("append", static_cast<void (MyString::*)(const MyString&, int, int)>(&MyString::append));

    // erase() сдвигает хвост влево. replace() создает копию источника,
    // затем вызывает erase() и insert(), чтобы использовать общий код вставки.
    cls.def("erase", &MyString::erase);
    cls.def("replace", static_cast<void (MyString::*)(int, int, const char*)>(&MyString::replace));
    cls.def("replace", static_cast<void (MyString::*)(int, int, const MyString&)>(&MyString::replace));
    cls.def("replace", static_cast<void (MyString::*)(int, int, const char*, int)>(&MyString::replace));
    cls.def("replace", static_cast<void (MyString::*)(int, int, const MyString&, int)>(&MyString::replace));
    cls.def("replace", static_cast<void (MyString::*)(int, int, const char*, int, int)>(&MyString::replace));
    cls.def("replace", static_cast<void (MyString::*)(int, int, const MyString&, int, int)>(&MyString::replace));

    // substr(index) -> substr(index, count) -> конструктор MyString(const char*, int).
    // Возвращается новый объект, а не ссылка на исходную строку.
    cls.def("substr", static_cast<MyString (MyString::*)(int) const>(&MyString::substr));
    cls.def("substr", static_cast<MyString (MyString::*)(int, int) const>(&MyString::substr));

    // operator+ копирует левый объект и вызывает append(); operator+= меняет сам объект.
    cls.def("__add__", static_cast<MyString (MyString::*)(const char*) const>(&MyString::operator+),
            py::is_operator());
    cls.def("__add__", static_cast<MyString (MyString::*)(const MyString&) const>(&MyString::operator+),
            py::is_operator());
    cls.def("__iadd__", static_cast<MyString& (MyString::*)(const char*)>(&MyString::operator+=),
            py::return_value_policy::reference_internal, py::is_operator());
    cls.def("__iadd__", static_cast<MyString& (MyString::*)(const MyString&)>(&MyString::operator+=),
            py::return_value_policy::reference_internal, py::is_operator());

    // Чтение символа -> operator[] const -> check_index().
    cls.def("__getitem__", static_cast<const char& (MyString::*)(int) const>(&MyString::operator[]));
    // Запись -> operator[] -> check_index(). Не допускаем '\0': это конец C-строки.
    cls.def("__setitem__", [](MyString& self, int index, const std::string& value) {
        if (value.size() != 1 || value[0] == '\0') {
            throw std::invalid_argument("expected one non-null byte");
        }
        self[index] = value[0];
    });

    // Все сравнения используют compare(); он сравнивает символы через operator[].
    cls.def("compare", &MyString::compare);
    cls.def("__eq__", &MyString::operator==, py::is_operator());
    cls.def("__ne__", &MyString::operator!=, py::is_operator());
    cls.def("__lt__", &MyString::operator<, py::is_operator());
    cls.def("__le__", &MyString::operator<=, py::is_operator());
    cls.def("__gt__", &MyString::operator>, py::is_operator());
    cls.def("__ge__", &MyString::operator>=, py::is_operator());

    // find(source) -> find(source, 0) -> find_chars(); результат -1, если совпадения нет.
    cls.def("find", static_cast<int (MyString::*)(const char*) const>(&MyString::find));
    cls.def("find", static_cast<int (MyString::*)(const MyString&) const>(&MyString::find));
    cls.def("find", static_cast<int (MyString::*)(const char*, int) const>(&MyString::find));
    cls.def("find", static_cast<int (MyString::*)(const MyString&, int) const>(&MyString::find));
}
```
