# Лабораторная работа № 2 — служба резервного копирования Windows

Учебная программа на **C11 и WinAPI**, которая работает как служба Windows:
выбирает файлы по маскам, создаёт ZIP и автоматически обновляет его при изменениях
в исходной папке. Архиватор miniz встроен в программу; внешний процесс для сжатия
не запускается.

## Возможности

- Фоновая работа без пользовательского интерфейса.
- Настройки в UTF-8-файле `backup.ini`: источник, путь ZIP, маски и интервал проверки.
- Рекурсивный обход папок с сохранением относительных путей в архиве.
- Отбор файлов по точному имени и маскам `*` / `?`; несколько правил объединяются по ИЛИ.
- Создание ZIP средствами встроенной библиотеки miniz.
- Автоматическое обновление **того же ZIP по настроенному пути** без перезапуска службы.
- Собственная консольная программа управления: `install`, `start`, `stop`, `remove`.
- Запуск, остановка и перезапуск через стандартную оснастку «Службы» и PowerShell.
- UNC-пути для источника и архива, в том числе имена файлов и папок на русском языке.
- Однократное копирование командой `once` без установки службы.
- Журнал `backup.log` и повторные попытки при временных ошибках доступа.

## Как работает обновление

```text
backup.ini → обход исходной папки → отбор по маскам → ZIP
                         ↑                          │
                         └──── пауза и проверка ────┘
```

При запуске служба создаёт первоначальную копию. Затем после каждой паузы сравнивает
относительные имена, размеры и содержимое выбранных файлов с записями архива.
Проверяются сами байты, поэтому изменение обнаруживается даже при прежнем размере
файла и сохранённом времени модификации.

Если выбранные файлы не изменились, ZIP остаётся нетронутым. При изменениях служба
формирует полный актуальный архив во временном файле рядом с основным и заменяет
готовый ZIP только после успешного завершения записи. При временной ошибке прежняя
копия сохраняется, в журнал добавляется `RETRY`, затем выполняется новая попытка.

Архив содержит текущий набор файлов: добавления, переименования и удаления
отражаются при следующем обновлении. История версий не сохраняется.

## Сборка

Проверенная среда: **Windows 10 x64, MinGW GCC 13.1, CMake и Ninja**.
Требуются CMake **3.20 или новее**, компилятор C11 и Python 3 для интеграционных
проверок и упаковки. Исходники miniz уже находятся в `third_party/`;
скачивать библиотеку при сборке не требуется.

Следующие команды выполняются в PowerShell **из каталога этой лабораторной**.
`gcc`, `cmake`, `ctest`, `ninja` и `python` должны быть доступны через `PATH`.

```powershell
cmake -S . -B build -G Ninja -DCMAKE_BUILD_TYPE=Release -DCMAKE_C_COMPILER=gcc
cmake --build build
ctest --test-dir build --output-on-failure
python tests/integration.py build/backup_probe.exe build/demo.exe
python tests/monitor_integration.py build/backup_probe.exe
python tools/package.py . build
python tests/cli_smoke.py dist/Lab2
```

Результат: `dist/Lab2/` и `dist/Lab2.zip`. Пакет содержит службу, тестовую программу,
пример DOCX, настройки, инструкции и PowerShell-сценарии. В Windows, где запускается
готовый пакет, компилятор и внешний архиватор не нужны.

Для MinGW рекомендуется путь к рабочей копии без кириллицы. Альтернативный сценарий
`build.ps1` использует инструменты CLion и создаёт junction с ASCII-путём. Пути к
CLion и Python передаются явно; например, при соответствующих каталогах установки:

```powershell
.\build.ps1 -ClionDirectory 'C:\Program Files\JetBrains\CLion' -PythonPath 'C:\Python313\python.exe'
```

`dist/Stage1` и `dist/Lab2-Stage1.zip` создаются как совместимые копии актуального
пакета для старой общей папки VirtualBox. Основной пакет — `dist/Lab2`.

## Быстрый запуск в Windows 10

1. Собрать пакет и скопировать содержимое `dist/Lab2` в виртуальную машину,
   например в `C:\Lab2Package`.
2. Открыть PowerShell **от имени администратора** и подготовить тестовую папку:

   ```powershell
   cd C:\Lab2Package
   powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\setup-demo.ps1
   cd C:\BSITLab2
   ```

   Скрипт создаёт источник с тремя уровнями вложенности, папку для ZIP и конфигурацию.
   На каждом из четырёх уровней находятся TXT, DOCX и EXE; из исходного набора под
   настроенные маски попадают 12 файлов. Служба пока не установлена.

3. Установить и запустить службу:

   ```powershell
   .\backup_service.exe install
   .\backup_service.exe start
   Get-Content .\backup.log -Tail 10
   ```

4. Дождаться строки `Backup ready: 12 files.` в журнале и открыть
   `C:\BSITLab2\backup\backup.zip`. Изменить выбранный TXT или добавить новый TXT
   во вложенную папку. После строки `Backup updated` заново открыть архив и проверить
   новое содержимое. Если просмотрщик удерживает ZIP и мешает замене, закрыть его:
   служба повторит попытку автоматически.
5. По завершении остановить службу и удалить её регистрацию:

   ```powershell
   .\backup_service.exe stop
   .\backup_service.exe remove
   ```

Для примера с `\\localhost\C$` нужны работающая служба Windows `Server`
(`LanmanServer`), доступный административный ресурс `C$` и соответствующие права.
Для другого сервера необходимо указать существующие общие папки и обеспечить
доступ к ним учётной записи службы.

## Команды управления

| Команда | Действие |
|---|---|
| `backup_service.exe install` | Регистрирует службу с ручным типом запуска |
| `backup_service.exe start` | Запрашивает запуск у SCM и ожидает состояния `RUNNING` |
| `backup_service.exe stop` | Запрашивает штатную остановку и ожидает `STOPPED` |
| `backup_service.exe remove` | Удаляет регистрацию остановленной службы |
| `backup_service.exe once` | Создаёт одну копию по настройкам рядом с EXE и завершается |
| `backup_service.exe once C:\config\backup.ini` | Создаёт одну копию по указанному файлу настроек |

Имя службы — `BSITLab2Backup`, отображаемое имя — `BSIT Lab 2 - Backup`.
Она работает в отдельном процессе от **LocalSystem**. После установки запускается
вручную; автоматический запуск при загрузке Windows не настраивается.

Состояние `RUNNING` означает, что служба запущена. Готовность первой копии проверяется
по `Backup ready` в журнале. Команда `remove` сохраняет EXE, настройки и ZIP на диске.
Запуск EXE без аргументов предназначен для SCM; из обычной консоли следует использовать
команды выше. Для управления через Windows доступны `services.msc`, `Stop-Service`
и `Restart-Service`.

## Конфигурация

Пример `backup.ini`, расположенного рядом с EXE:

```ini
source=\\localhost\C$\BSITLab2\source
archive=\\localhost\C$\BSITLab2\backup\backup.zip
mask=*.txt
mask=report_?.docx
mask=demo.exe
interval_seconds=2
```

| Параметр | Значение |
|---|---|
| `source` | Существующая исходная папка, обычный UNC-путь |
| `archive` | Полный UNC-путь ZIP; родительская папка должна существовать |
| `mask` | Правило отбора по имени файла; можно указать до 16 правил |
| `interval_seconds` | Пауза между проверками: целое от 1 до 3600, по умолчанию 2 |

`source` и `archive` обязательны, нужен хотя бы один `mask`. Кодировка — UTF-8
с BOM или без него. Разрешены пустые строки и комментарии с `#` или `;`.
Изменения настроек применяются после перезапуска службы.

Маска проверяется для имени файла на каждом уровне вложенности без учёта регистра:

| Правило | Подходит | Не подходит |
|---|---|---|
| `*.txt` | `note.txt`, `ЗАМЕТКА.TXT` | `note.docx` |
| `report_?.docx` | `report_1.docx` | `report_12.docx` |
| `demo.exe` | `demo.exe` | `other.exe` |

`*` означает любое число символов, включая ноль; `?` — один символ.
`*.*` требует точку в имени; для всех имён используется `*`. Это собственная
проверка масок программы, правила не зависят от поведения Проводника.

## Устройство проекта

| Путь | Назначение |
|---|---|
| `src/main.c` | Консольные команды SCP, регистрация в SCM, состояния и остановка службы |
| `src/monitor.c` | Цикл проверки изменений, обновление архива и повторные попытки |
| `src/backup.c` | Чтение настроек, маски, обход папок, сравнение и создание ZIP |
| `src/common.c`, `src/app.h` | Пути, журнал, ошибки и общие объявления |
| `samples/demo.c` | Тестовая программа с окном для проверки извлечённого EXE |
| `tests/` | Проверки конфигурации, масок, ZIP и автоматического обновления |
| `scripts/` | Подготовка демонстрации и проверка настоящей службы |
| `tools/package.py` | Сборка демонстрационного пакета и SHA-256-манифеста |
| `third_party/miniz/` | Исходники встроенной библиотеки архивирования |

SCM управляет службой Windows. Роль SCP выполняет этот же EXE, запущенный с командой
`install`, `start`, `stop` или `remove`. При штатной остановке обработчик устанавливает
событие, основной цикл завершает работу и освобождает ресурсы.

## Проверки

CTest проверяет маски и загрузку конфигурации. Python-проверки независимо читают
полученные ZIP средствами стандартной библиотеки и сверяют имена, CRC и содержимое.
Проверяются вложенность, Unicode, пустые и большие файлы, отмена копирования,
блокировки, обновления без изменения длины или времени файла, добавление,
переименование, удаление и восстановление отсутствующего или повреждённого архива.

Для проверки **настоящей службы** после подготовки демонстрационного каталога
в PowerShell администратора:

```powershell
cd C:\BSITLab2
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\verify-complete.ps1 -KeepInstalled
```

Этот сценарий управляет службой `BSITLab2Backup`: проверяет установку, запуск,
содержимое ZIP, автоматические обновления при неизменном PID, повтор после блокировки,
перезапуск, остановку и удаление. С `-KeepInstalled` в конце оставляет службу
установленной и работающей. Результаты записываются локально.

## Ограничения

- Обновление выполняется периодически с полной пересборкой ZIP. Задержка включает
  паузу, время сравнения и архивации; для больших объёмов это затратный подход.
- Сохраняется текущий набор файлов без истории версий и шифрования.
- Пути ограничены 259 единицами UTF-16, вложенность — 32 уровнями,
  количество масок — 16, длина одной маски — 127 единицами UTF-16.
- Reparse points и junction пропускаются. Единого согласованного снимка всех файлов
  через VSS нет; изменения во время обхода могут попасть в следующую копию.
- Конфликтующий доступ к исходному файлу или ZIP приводит к повторной попытке.
  Длительный сетевой ввод-вывод может задерживать остановку.
- Доступ к UNC выполняется от имени службы. Проверка через localhost не гарантирует
  доступ к другому серверу. Для удалённых ресурсов нужна подходящая учётная запись.
- LocalSystem используется для учебной среды. Каталог службы и её конфигурация
  должны быть защищены от изменения недоверенными пользователями.
