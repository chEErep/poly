# Полный показ лабораторной 2

Это сценарий единой сдачи всей работы. Автоматическое обновление уже реализовано.
Все команды выполняются внутри Windows 10, в PowerShell администратора.

## Подготовка перед преподавателем

1. Обновить пакет через `\\VBOXSVR\lab2-stage1\update-demo.ps1` либо скопировать `dist/Lab2`.
2. Проверить результат автоматической репетиции: все строки PASS, без ошибки в конце.
3. Перейти в каталог и открыть «Службы»:

```powershell
cd C:\BSITLab2
services.msc
```

4. Если наша служба есть, перед показом выполнить stop и remove, затем обновить список.
   Если службы нет, эти две команды не нужны.
5. Закрыть прошлые окна ZIP и тестовую программу. Открыть Проводник в `C:\BSITLab2`.
   Исходные документы не удалять. Если файл `новый.txt` остался после вашей репетиции,
   для следующего показа можно создать другое новое имя, например `новый2.txt`.

## 1 Установка

```powershell
.\backup_service.exe install
```

Обновить список F5. Служба `BSIT Lab 2 - Backup` появилась, пока остановлена.
Сказать: «Установка зарегистрировала службу; запуск будет отдельной командой».

## 2 Настройки и правила

Открыть `backup.ini`. Объяснить source, archive, mask и interval_seconds=2.
UNC `\\localhost\C$\...` означает обращение к административному ресурсу самой виртуалки.
Показать source и `папка1\папка2\папка3`.

При исходном наборе выбираются `заметка.txt`, `report_1.docx`, `demo.exe` на каждом
из четырёх уровней: всего 12 файлов. `report_12.docx` и `other.exe` исключаются.
Если в папку уже добавлялись подходящие файлы, общее число может быть больше 12.

## 3 Запуск и первая копия

```powershell
.\backup_service.exe start
Get-Content .\backup.log -Tail 10 -Encoding UTF8
```

В «Службах» состояние «Выполняется». В журнале дождаться свежего `Backup ready`.
Статус RUNNING сам по себе ещё не подтверждает окончание архивации.
Открыть `backup\backup.zip`, показать нужные файлы и вложенные папки.

## 4 Главный пункт Автоматическое обновление

Службу не останавливать и команду start повторно не выполнять.
Закрыть просмотрщик ZIP перед редактированием исходных файлов.

1. В исходной папке открыть `заметка.txt`, дописать строку «Изменено для защиты»,
   сохранить Ctrl+S и закрыть документ.
2. В `source\папка1\папка2\папка3` создать новый `новый.txt`, записать «Новый файл»
   и сохранить. При скрытых расширениях включить в Проводнике «Расширения имён файлов».
3. Подождать несколько секунд; в журнале дождаться `Backup updated`.
4. Заново открыть тот же `backup\backup.zip` и при необходимости обновить Проводник F5.
5. Показать изменённый текст и новый файл в третьей вложенной папке.
6. Показать, что служба по-прежнему «Выполняется».

Сказать: «Изменения попали в тот же настроенный ZIP без перезапуска службы.
Она периодически сравнивает выбранные файлы с архивом и обновляет его при различиях».

Пауза по умолчанию 2 секунды плюс время проверки/записи. Если файл занят,
служба сохраняет прежнюю копию и повторяет попытку. В журнале это строка RETRY.

## 5 Чтение и запуск EXE

Не останавливая службу, открыть ZIP штатным просмотрщиком Windows.
Извлечь `demo.exe` в отдельную папку и запустить полученную копию.
Появится тестовое окно. Закрыть окно и просмотрщик ZIP перед следующим шагом.

## 6 Перезапуск и остановка

В «Службах» выбрать «Перезапустить», дождаться новой записи `Backup ready`.
Затем остановить службу кнопкой оснастки.
Для собственной команды показать:

```powershell
.\backup_service.exe start
```

Дождаться готовности, затем:

```powershell
.\backup_service.exe stop
```

## 7 Удаление регистрации

```powershell
.\backup_service.exe remove
```

Обновить список F5; если запись удерживается, закрыть свойства и оснастку, открыть заново.
EXE, настройки, исходные файлы и архив остаются на диске.

## Если возникла ошибка

- 5: нужны права администратора или доступ к файлу/ресурсу.
- 1073: служба уже установлена; сначала stop/remove.
- 1060: службы нет; сначала install.
- 1063: EXE запущен без команды вне SCM; используйте install/start либо once.
- 32 либо RETRY: файл занят; закройте редактор/ZIP и дождитесь повторной попытки.
- Нет свежего Backup ready/updated: прочитайте последние строки backup.log.
- Пути source/archive проверяются для учётной записи службы, а не только для Проводника.
