# БСИТ — лабораторная работа №1

Текущий этап: простой демонстрационный прототип на чистом C.

Уже реализовано:

- TCP-сервер под Windows;
- обработка клиентских сокетов через IO Completion Port;
- несколько worker threads;
- собственный 24-байтный заголовок протокола;
- корректная обработка частичного приёма и отправки;
- несколько запросов в одном соединении;
- `GET_OS`, `GET_TIME`, `GET_UPTIME`, `GET_MEMORY`;
- консольная диагностика подключений и запросов;
- проверка кодирования/декодирования заголовка.

Пока не реализовано:

- CryptoAPI и установка сеансового ключа;
- шифрование запросов и ответов;
- диски;
- ACL и владелец;
- ключи реестра;
- `AcceptEx` для асинхронного принятия соединений;
- корректная управляемая остановка worker threads.

Это не полная готовая лабораторная. Это первый рабочий слой, который будет
расширяться без замены протокола и основной архитектуры.

## Самая простая сборка

Из-за кириллицы в полном пути MinGW/Ninja может исказить имена каталогов. Для
этого в проекте есть `build_stage1.ps1`: он создаёт junction с ASCII-путём,
добавляет MinGW в `PATH`, собирает проект и запускает тест.

Из PowerShell в папке проекта:

```powershell
.\build_stage1.ps1
```

Junction `C:\Users\<имя>\bsit_lab1_workspace` указывает на настоящую папку
проекта. Это не копия: изменения видны с обеих сторон.

## Сборка в CLion

1. Один раз запустить `build_stage1.ps1`, чтобы создать ASCII-junction.
2. Открыть в CLion папку `C:\Users\<имя>\bsit_lab1_workspace`, а не путь с
   кириллицей.
3. Убедиться, что выбран MinGW toolchain из CLion.
4. Дождаться загрузки CMake.
5. Собрать цели `lab_server`, `lab_client` и `protocol_tests`.

Командная сборка уже автоматизирована в `build_stage1.ps1`. Вручную повторять
длинную CMake-команду не требуется.

## Запуск на одном компьютере

В первом терминале:

```powershell
.\build-ok\lab_server.exe
```

Во втором терминале:

```powershell
.\build-ok\lab_client.exe 127.0.0.1
```

Порт по умолчанию — TCP 27015. Другой порт передаётся первым аргументом серверу
и вторым аргументом клиенту:

```powershell
.\build-ok\lab_server.exe 29001
.\build-ok\lab_client.exe 127.0.0.1 29001
```

## Запуск через виртуальную машину

1. Запустить `lab_server.exe` внутри VM.
2. Узнать адрес VM командой `ipconfig`.
3. Разрешить входящий TCP-порт программы в Windows Firewall только для Private
   network profile.
4. На хосте выполнить:

```powershell
.\build-ok\lab_client.exe IP_ВИРТУАЛЬНОЙ_МАШИНЫ 27015
```

Рекомендуемая конфигурация VirtualBox: Host-only Adapter для стабильной и
изолированной связи host ↔ VM, плюс отдельный NAT-адаптер для интернета внутри
VM. Bridged Adapter для этой лабораторной не обязателен.
