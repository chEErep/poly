# Первый показ лабораторной и настройка VirtualBox

## 1. Решение по срокам

План: **целиться в полную сдачу на второй из трёх оставшихся пар**.

Ближайшая пара через два дня нужна не для попытки выдать незавершённую работу за
готовую, а для ранней демонстрации архитектуры и получения замечаний преподавателя.
На ней показывается:

- IOCP-сервер на чистом C;
- консольный клиент;
- собственный формальный протокол;
- четыре запроса о системе;
- несколько подключений;
- связь с виртуальной машиной, если VM уже будет установлена.

После этого добавляются диски, ACL и CryptoAPI. Если преподаватель на первом
показе подтвердит архитектуру, на второй паре выполняется полный сценарий сдачи.
Третья пара остаётся резервом, а не основным сроком.

## 2. Что скачать

Скачивать только с официальных сайтов.

### VirtualBox

Официальная страница:

<https://www.virtualbox.org/wiki/Downloads>

Нужно скачать:

1. **VirtualBox Platform Package — Windows hosts**.
2. **Oracle VirtualBox Extension Pack** точно той же версии.

Extension Pack потребуется для полноценного USB 2.0/3.0 passthrough, который
понадобится при демонстрации появления флешки. Для личного/учебного использования
на странице действует отдельная лицензия PUEL — её нужно прочитать и принять.

Не нужно скачивать SDK и исходный код VirtualBox.

### Образ Windows

Для этой лабораторной рекомендуется Windows 10 Enterprise LTSC 2021 Evaluation:

<https://www.microsoft.com/en-us/evalcenter/download-windows-10-enterprise>

Выбрать:

- `Windows 10 Enterprise LTSC`;
- версия LTSC 2021, если Microsoft показывает название версии;
- 64-bit ISO;
- можно English (United States), чтобы интерфейс и диагностические сообщения
  совпадали с большинством документации.

Это официальная полнофункциональная 90-дневная evaluation-версия, ключ продукта
для установки не требуется. После скачивания желательно сверить SHA-256 с
опубликованным Microsoft значением.

Обычная Windows 10 22H2 снята с поддержки 14 октября 2025 года, поэтому её для
новой VM не выбирать. Windows 10 Enterprise LTSC 2021 получает обновления до
января 2027 года, чего достаточно для текущего учебного курса. Тем не менее VM
остаётся учебным стендом: не хранить в ней реальные секреты и документы и не
выставлять лабораторный TCP-сервер в общедоступную сеть. Для связи с хостом
использовать Host-only Adapter.

## 3. Параметры VM

Начальная конфигурация:

- имя: `BSIT-Lab1-Server1`;
- тип: Microsoft Windows;
- версия: Windows 10 (64-bit);
- RAM: 4096 MiB, если на хосте хватает памяти;
- CPU: 2;
- виртуальный диск: 40–50 GiB, dynamically allocated;
- EFI: не требуется, стандартного виртуального BIOS достаточно;
- TPM 2.0 и Secure Boot: не требуются;
- ISO: официальный Windows 10 Enterprise LTSC 2021 Evaluation, 64-bit.

Если хосту тяжело, после установки можно уменьшить RAM до 3072 MiB, но 4 GiB
удобнее для первоначальной установки.

## 4. Сеть VM

Самый понятный вариант для лабораторной:

1. Adapter 1 — **NAT**, чтобы VM имела интернет.
2. Adapter 2 — **Host-only Adapter**, чтобы хост и VM стабильно видели друг друга.

Преимущество Host-only: IP не зависит от сети университета, а лабораторный сервер
не выставляется в общую сеть.

После запуска VM:

1. Выполнить внутри VM `ipconfig`.
2. Найти IPv4 host-only адаптера, часто это сеть вида `192.168.56.0/24`.
3. С хоста выполнить `ping IP_VM`.
4. Если ping запрещён firewall, проверить TCP после добавления правила для порта
   27015.

Временное правило Windows Firewall внутри VM нужно ограничить:

- программой `lab_server.exe` или TCP-портом 27015;
- только Private profile;
- по возможности только host-only подсетью.

Не нужно полностью отключать firewall.

## 5. USB для будущей демонстрации

После установки Extension Pack:

1. Выключить VM.
2. Открыть Settings → USB.
3. Выбрать USB 3.0 (xHCI) Controller.
4. Добавить filter для тестовой флешки либо подключить её через меню Devices →
   USB после запуска VM.
5. Убедиться, что флешка отключилась от хоста и появилась внутри гостевой Windows.

Перед извлечением использовать безопасное извлечение в гостевой системе.

## 6. Как собрать проект

В PowerShell из папки лабораторной:

```powershell
.\build_stage1.ps1
```

Скрипт:

- проверяет пути к GCC, CMake и Ninja из CLion;
- создаёт ASCII-junction, потому что MinGW/Ninja некорректно обрабатывал текущий
  кириллический путь;
- конфигурирует CMake;
- собирает программы;
- запускает `protocol_tests`.

## 8. Как показать с VM

Вариант A — сервер внутри VM:

1. Скопировать `lab_server.exe` в VM.
2. Разрешить для него TCP 27015 в Private profile.
3. Запустить сервер.
4. Узнать host-only IP виртуальной машины.
5. На хосте выполнить:

```powershell
C:\Users\chere\bsit_lab1_workspace\build-ok\lab_client.exe IP_VM 27015
```

Вариант B — сервер на хосте, клиент внутри VM — технически тоже работает, но для
объяснения задания вариант A лучше: агент-сервер находится на наблюдаемой машине.

## 9. Короткая речь для первого показа

> Я разрабатываю распределённую систему сбора информации. Агент является
> сервером и постоянно ждёт запросы, а центральный клиент инициирует соединение.
> Сейчас готов первый слой: собственный формализованный протокол и серверная
> обработка соединений через IO Completion Port. TCP является потоком байтов,
> поэтому каждому сообщению предшествует 24-байтный заголовок с magic, версией,
> типом, request ID и длиной payload. Сервер корректно накапливает частично
> пришедший заголовок и тело. В одном соединении клиент может отправить несколько
> запросов: версию ОС, время, uptime и состояние памяти. Диски, ACL и CryptoAPI
> являются следующими этапами и сейчас ещё не заявляются как готовые.

## 10. Что показать по шагам

1. Показать `protocol.h` и перечисление четырёх запросов.
2. Запустить сервер и обратить внимание на число worker threads.
3. Запустить клиент, выбрать каждый запрос.
4. На сервере показать журнал с `peer`, `request_id` и типом запроса.
5. Запустить ещё один клиент в отдельном окне.
6. Если VM готова — повторить запрос по IP виртуальной машины.
7. Честно назвать следующие этапы: диски → ACL → CryptoAPI → Wireshark.

## 12. Возможные вопросы преподавателя

### Почему принятие соединения пока выполняется обычным `accept`, а не `AcceptEx`?

IOCP уже используется для асинхронного `WSARecv` и `WSASend` всех подключённых
клиентов, то есть параллельная обработка сетевых операций выполнена через порт
завершения. `AcceptEx` будет следующим улучшением, но он не нужен для проверки
framing и обработчиков первых запросов. Это ограничение текущего этапа, а не
финальной версии.

### Почему клиент блокирующий?

Требование IOCP относится к масштабируемому серверу. Центральный клиент управляется
одним пользователем и одновременно ждёт один выбранный ответ, поэтому блокирующая
реализация проще и достаточна.

### Почему нельзя считать, что один `send` соответствует одному `recv`?

TCP передаёт поток байтов и не сохраняет границы вызовов. Поэтому сервер сначала
накапливает ровно 24 байта заголовка, затем указанное в нём число байтов payload.

### Почему стоит ограничение 64 KiB?

Длина приходит от недоверенного клиента. Без максимума атакующий может заставить
сервер выделить огромный буфер. Для текущих текстовых системных ответов 64 KiB
достаточно.

### Это уже готовая лабораторная?

Нет. Готов и проверен сетевой/IOCP слой и четыре запроса. До полной сдачи нужны
диски, ACL, владелец, CryptoAPI, сеансовый ключ и демонстрация в Wireshark.

## 13. Ошибка VirtualBox Hardening из-за Windhawk

На текущем компьютере VirtualBox 7.2.18 может завершаться до запуска VM с ошибкой:

```text
VERR_SUP_VP_FOUND_EXEC_MEMORY
NtCreateFile(\Device\VBoxDrvStub) failed
```

Папка VM и кириллица в пути не являются причиной этой ошибки. В
`VBoxHardening.log` зафиксировано внедрение `windhawk.dll`, библиотек Windhawk и
мода `explorer-details-better-file-sizes` в `VirtualBoxVM.exe`. VirtualBox
Hardening обнаруживает постороннюю исполняемую память и специально останавливает
процесс.

Быстрая проверка причины:

1. Полностью закрыть VirtualBox Manager.
2. Через значок Windhawk в системном трее выполнить выход из Windhawk.
3. Снова открыть VirtualBox и запустить VM.

Постоянное исправление:

1. Открыть Windhawk.
2. Перейти в `Settings` → `Advanced settings` → `More advanced settings`.
3. В `Process exclusion list` добавить по одной строке:

```text
D:\VirtualBox\*
VirtualBox.exe
VirtualBoxVM.exe
VBoxSDS.exe
VBoxSVC.exe
```

4. Нажать `Save and restart Windhawk`.
5. Полностью закрыть ранее запущенные процессы VirtualBox и открыть VirtualBox
   заново. Если есть сомнения, один раз перезагрузить Windows.

Не нужно отключать Microsoft Defender, Memory Integrity, DEP, Secure Boot или
переустанавливать VM. Драйверы VirtualBox на текущем компьютере загружены и
работают; конфликт находится в user-mode code injection со стороны Windhawk.
